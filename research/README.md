# research

The Python half of the repository: the experiment configs, the scripts that turn them into results, the committed results with their manifest, the statistics the pre-registration names, and the thesis drafts made from the log. It is a uv workspace member (`research/pyproject.toml`, Python 3.12, numpy and scipy). Part I of the thesis rests on it, so a regression here is a thesis problem. Back to the [root README](../README.md).

## What is here

| path | what |
|---|---|
| `configs/` | one JSON file per result or run. Experiment configs (`h1-gatemem.json`, `h1-mem-inv.json`, `h2-longmemeval-c2.json`, `h2-longmemeval-c5-medium.json`, `h3-lint-model.json`, `l3-pilot.json`) are run by `make run` with a named model; fixture configs (`b3-*`, `b5-*`, `b7-merit-fixture.json`, `b11-tau2-fixture.json`, `rn1-*`, `x1-*`, `*-fixture.json`) replay committed cassettes; the rest configure a research script |
| `scripts/` | one script per result, each run as `python research/scripts/<name>.py --config <config> --out <file>`; `results_io.py` holds the shared helpers; `reproduce.py` is `make test-repro`; `consolidate_log.py` is `make thesis` |
| `results/` | the committed results, and [`results/MANIFEST.md`](results/MANIFEST.md), one row per file: config, script, commit and sha256 |
| `analysis/` | the pre-registration's Statistics section as code: `bootstrap.py` (paired BCa bootstrap), `equivalence.py` (H4's two one-sided score tests), `holm.py`, `wilson.py`, `h1.py` (the H1 table), `power.py` (H4's sample size), `effects.py` (effect sizes beside the test) |
| `tests/` | pytest: the analysis on synthetic data with planted effects and planted nulls (`test_analysis.py`, `test_equivalence.py`), the pre-registration's completeness (`test_prereg.py`), the reproduce loop on a toy manifest, the run limits, and one test file per script |
| `engram_types/` | the schema as Python `TypedDict`s, generated by `make api`; do not edit |
| `thesis/drafts/` | the chapter drafts `make thesis` writes from `docs/log/`: one file per chapter, plus the timeline, the limitations, the results index and the decisions |

## How a result is made real

AGENTS.md rule 9: no result is real unless `research/scripts/<name>.py` regenerates it from `research/configs/` into `research/results/`. In practice:

1. **A config** names every input: the data and its pinned hash, the seeds, the run folders it reads.
2. **A script** reads the config, calls no model, and writes a byte-stable file: sorted keys, floats rounded to six decimals, no timestamps, no absolute paths (`results_io.write_result`). A script that needs pinned benchmark data fetches it into `.engram/upstream/` at the pinned commit (data only, refused under `ENGRAM_OFFLINE=1`).
3. **A manifest row** in `results/MANIFEST.md` records the file, config, script, commit and sha256. `research/tests/test_prereg.py` requires every row to map to exactly one hypothesis's results glob (`h1-*` to `h5-*`).
4. **A log entry** of type `measurement` cites the file; `make thesis` rejects one whose hash does not match the manifest.

A number typed into a document by hand does not exist. A live run's numbers become results the same way: the run writes `.engram/runs/<name>/`, and a script (for H1, `make h1-table`, then `make h1-figure`) turns it into a manifest row.

## Reproduce

```sh
uv sync
make test-repro                                    # every manifest row, compared by sha256
uv run python research/scripts/cost_table.py --config research/configs/cost-table.json --out /tmp/h2-cost-table.json
sha256sum /tmp/h2-cost-table.json                  # 074d4fb0... as in the h2-cost-table.json row of results/MANIFEST.md
uv run pytest research                             # the statistics and the scripts' tests
```

`make test-repro` takes about 17 minutes on 32 cores; `ENGRAM_RESEARCH_WORKERS=<n>` caps its worker processes without changing any byte. A fresh clone needs the network once, for pinned benchmark data. CI does not run it; it is run by hand before a PR that adds or changes a result merges.

For the live experiments, the pipeline is in AGENTS.md's command list: `make run CONFIG=<experiment config> COUNT=1` counts the sessions with no model called; `MODEL=<provider/model> LIVE=1` runs them (with a key, after the tag); `REPLAY=1` replays that run's cassettes offline; then the table and figure scripts.
