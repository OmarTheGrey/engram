# E2.7 Counterexample tests for the two suspected trust gaps

Status: open.

From `docs/tasks/absorb-plan.md`, pull request 3 of 30 (research plans R-003 in `docs/research/absorb/long-list.md`). Lane: research. Week: W8. Effort: S. Read AGENTS.md, the plan's entry for this card and `docs/conventions/absorption.md` before starting.

Goal: Each suspected trust gap is proved or refuted by a committed test, before anything is changed: (1) a write whose actor names no source keeps the provenance kind its caller claims; (2) a budget eviction, a retire or a rewrite by a less trusted source removes or changes a more trusted item.

Why: The source-level readers of the GitHub sweep found both by reading, not by running. The first is documented behaviour (ADR 0004, decision D4: `withPlaneProvenance` in `packages/core/src/plane/write.ts` lets the caller's provenance stand when the actor has no source); whether it is a gap depends on which surfaces can reach the plane without a source. The second is unconfirmed.

Steps:

1. One new test file. Every test that asserts the safe behaviour is written with `it.fails`, so the suite stays green whichever way it comes out, and a later fix turns it into a plain test.
2. The lattice: for each pair of the seven provenance kinds as writer and victim, and each of rewrite, retire and budget eviction, assert that the less trusted writer does not change or remove the more trusted active item unless the owner acts.
3. The floor: a write through `Plane.write` by an actor with no `source`, claiming kind `user`. Then list which surfaces (CLI, MCP, HTTP, pi extension, library callers) can produce such an actor today.
4. One `finding` log entry per gap with its reproduction command, whether confirmed or refuted. A refuted gap is removed from card E2.11.
5. Check whether a confirmed gap can change a registered H1 to H4 number, and say so in the entry. Report, do not hide.

Absorbs (mode per ADR 0037):

- dent8 (Apache-2.0 or MIT, idea): the exhaustive kind by kind by operation lattice as a test shape.
- Veracium (MIT, idea): the expectation that an unattested write lands at the least trusted kind.

Files: packages/core/test/counterexamples/trust.test.ts (new), docs/log/

Depends on: none

Decision: none. What to do about a confirmed gap is item 51 (ADR 0040).

Acceptance: `make test-one T=packages/core/test/counterexamples/trust.test.ts` and `make test`

Risks: A confirmed gap may touch a registered condition; that is a finding for the lead before the tag, not something to fix here.

Out of scope: any change under `packages/core/src/` (the fix is card E2.11); the lead-owned invariants file; anything in another package; schema changes unless the card says so (AGENTS.md rule 5)
