Goal: Given a new item and its candidate predecessors, core proposes which older items should get an end date and which need a person's review, and resolves the current head of a supersession chain safely.

Why: STALE and the revocation study show stores failing at exactly this: a newer fact arrives and the old one stays valid. Engram has `valid_to` and lineage and nothing that proposes an end date. Graphiti has the interval logic and it is Apache-2.0.

Steps:

1. A pure function: new item and candidates in, a list of proposals out (set `valid_to` to the new item's `valid_from`, or flag for review). Overlapping or contradictory intervals always go to review. Nothing is retired automatically.
2. `supersede.ts`: a cycle-safe head resolver over lineage, with typed errors for an unknown id, a cycle, or a chain deeper than 32, and a deterministic choice at a fork.
3. The CLI and the MCP server apply an accepted proposal as an ordinary governed update through `Plane.write`, so the gate decides and an event is logged.
4. A property test: the resolver terminates on every generated lineage, and applying every proposal never leaves two active items with the same key and overlapping validity.
5. The fixtures and every committed result stay byte-identical: the helper is called by nothing in the read path.

Absorbs (mode per ADR 0037):

- Graphiti (Apache-2.0, port): the interval logic of its temporal invalidation (re-read the source at a pinned commit before porting).
- gaptime (Apache-2.0, port): the Allen interval helper.
- Remnic (MIT, copy): `shared-context/supersession-chain.ts`, the chain resolver.
