# E1.6 The tamper-evident event log

Status: open.

From `docs/tasks/absorb-plan.md`, pull request 21 of 30 (research plans R-029, R-030 in `docs/research/absorb/long-list.md`). Lane: research. Week: W14. Effort: L. Read AGENTS.md, the plan's entry for this card and `docs/conventions/absorption.md` before starting.

Goal: An edit, a deletion, a reorder or a truncation of the event log is detected by `engram log verify`, and an offboarding's erasure of a person's content still leaves the log verifiable.

Why: Every guarantee Engram gives is read off its log, and the log is append-only by convention only: nothing stops a row being edited in the database. Offboarding makes a plain hash chain impossible, because it rewrites event bodies to erase content. ADR 0038 is the design that keeps both.

Steps:

1. A side table created in `packages/core/src/db/migrate.ts`: per event, a chain hash over the previous hash and a skeleton that covers every field of the event and holds no content. A field offboarding never redacts (the reason among them) is hashed as it is; a field it may redact is represented by a salted commitment, so an erasure deletes the salt and the commitment still stands. `schema.ts` does not change.
2. One canonical-JSON function used by the writer and the verifier (UTC timestamps at fixed precision, integral numbers, sorted keys), with RFC 6962's leaf and node prefixes, a genesis per log, and a head-and-count anchor in a meta row against tail truncation.
3. The chain starts after the migrations that rewrote bodies in place, with a backfill checkpoint that says so.
4. Signed checkpoints: the signing function is injected, so core does no key I/O. The CLI supplies an Ed25519 key the operator holds.
5. `engram log verify`: an ordered verifier that reports the first broken link, and UNSIGNED as a verdict of its own when a checkpoint carries no signature. A link whose salts are gone verifies as erased only when the chain itself holds an offboarding erase event for that item; a missing salt with no such event is reported as tampering.
6. A property test on SQLite and Postgres: random operations including an offboarding, then an injected edit, deletion, reorder and tail truncation, each detected, together with a rewritten reason and a forged redaction (a field blanked and its salt deleted with no erase event). It lives in its own file, `chain.test.ts`, which `make test-invariants` runs, and is counted as the next invariant in AGENTS.md (the ninth if card E2.11 has landed, the eighth otherwise). The lead-owned invariants file is not edited.
