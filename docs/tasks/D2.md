Rewritten on 2026-11-21 by the absorb plan. Roadmap v1's card was "Induction using a published method (Agent Workflow Memory or Trace2Skill, cited); candidates as procedural items with SKILL.md body and tool allowlist", files `procedures/induce.py`, acceptance "candidates produced for a fixture session set". Under ADR 0001 the paths are the TypeScript layout in AGENTS.md.

Goal: Recorded sessions go in, candidate procedures come out: procedural items with status `candidate`, a SKILL.md body and a tool allowlist, induced by a port of Agent Workflow Memory with every model call seeded and cached.

Why: ADR 0012 chose Agent Workflow Memory: it is the published method H5 names, and its code is Apache-2.0. Writing each candidate in the Agent Skills format means Claude Code and pi can load an admitted procedure without a converter.

Steps:

1. `skill.ts` in core: pure `toSkillMd(item)` and `parseSkillMd(text)`, with the name, description and allowed-tools rules of the Agent Skills specification. Expected outputs are generated offline with the specification's own validator and committed.
2. The induction as `Distiller.distill` with an injected `ModelCall`: AWM's prompts, adapted from web tasks to tool-use sessions. The adaptation is written down in the card's pull request and the log, prompt by prompt.
3. Abandoned branches go to the prompt as negative evidence. A rule-based induction (the most frequent successful tool sequence) is the control that calls no model.
4. Candidates are written through `Plane.write` as procedural items with status `candidate` and lineage to the sessions they came from.
5. Fixture sessions from card D1, a scripted model, committed cassettes: a rerun makes zero new calls.

Absorbs (mode per ADR 0037):

- agent-workflow-memory (Apache-2.0, port): the induction method and its prompts, with attribution in `NOTICE` and the adaptation stated.
- Agent Skills specification (Apache-2.0, idea): the SKILL.md format and its validator, used offline.
