# X21 The H1 table counts the utility sessions the turn limit capped

Status: planned, gate work (2026-11-25). Pre-tag condition 3, second half (lead-decisions item 15).

From `docs/tasks/absorb-plan-2.md`, section 9, "Gate work cards (2026-11-25)". Lane: research. Week: W8, merged by 30 November. Effort: S. Read AGENTS.md, the pre-registration's Statistics section ("Seeds and exclusions") and the header of `research/analysis/h1.py` before starting.

Goal: The H1 table reports, per arm and condition, how many GateMem utility sessions the turn limit capped, beside the exclusion counts it already reports, so the sessions that leave MGS's U are visible where the result is read.

Why: Pre-tag condition 3 says items 14 and 15 are built before the tag, and the Statistics section says this one is not. Today a capped utility session reaches the table as a utility row with `utility_ok: null` (`packages/runner/src/research/h1-sessions.ts`, line 152), the same as a utility session whose judge gave no verdict, and the schema forbids an `exclusion` on a utility row (`research/analysis/h1.py`, line 224). So U loses those sessions silently, which item 15 answered (a) against.

Sources: pre-registration, pre-tag condition 3, Statistics and H1; `docs/tasks/lead-decisions.md`, item 15 and its row (a); backlog row "Capped utility sessions in the H1 table".

What already exists (checked on main at `09a1d85c`): the GateMem probe marks a capped session `excluded: "turn limit"` whatever its kind; the converter drops a capped violation session under its exclusion reason and a capped utility session to a null verdict; the table counts excluded violation sessions by reason (`_exclusions`) and computes MGS's U from non-null verdicts.

Steps:

1. Tests first in `research/tests/test_h1_exclusions.py`: a sessions file with two capped utility sessions under C4 and one under C5, and one utility session with no judge verdict, gives a capped-utility count of 2 and 1, and U unchanged from today's value; a capped flag on a non-utility row is a schema error.
2. The converter writes the turn limit on a capped utility row as an optional field (for example `capped: true`; name it in a `decision` entry), and the schema in `h1.py` accepts it on utility rows only. Decide in the same entry whether that is a new schema version (`h1-sessions/3`) or an optional field of version 2, as version 2 added `exclusion`.
3. The table writes the count per arm and condition, zero included, next to `exclusions`.
4. Update every test expectation under `research/tests/` that holds a whole table (`test_h1_pipeline.py`, `test_h1_secondary.py`) with the new key, and nothing else in them.
5. A `change` entry; a `decision` per choice above.
