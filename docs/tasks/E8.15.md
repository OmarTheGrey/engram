# E8.15 The engram terminal interface

Status: the design stage is done (`docs/design/tui.md`, `docs/decisions/0044-cli-tui.md`, this card and the `2026-11-21-e8-15-*` and `2026-11-22-e8-15-*` log entries). The implementation is on the experimental branch `cliupgrade`, not merged into main, in five parts. E8.15a (the registry and the plain CLI's additions), E8.15b (the frame), E8.15c (memory and audit screens, `@engram/view`) and E8.15d (policy, surfaces, machine and data screens): each implemented, independently reviewed, fixed and verified, then merged into `cliupgrade` (their `2026-11-22-e8-15a-*` to `2026-11-23-e8-15d-*` log entries). E8.15e (accessibility, line mode and the manual check): implemented and its gates passed on `cliupgrade` on 2026-11-25 (`docs/log/2026-11-25-e8-15e-milestone-final-gates.md`; `packages/cli/src/tui/line.ts`, `words.ts`, `asks.ts`, `validate.ts`, the section 11 audit in `packages/cli/test/tui/access.test.ts`, the pseudoconsole smokes in `test/e2e/tui.e2e.test.ts`, `docs/design/tui-manual-check.md`, the README section, the `2026-11-23-e8-15e-*` log entries), not yet independently reviewed. ADR 0044 stays proposed until the lead accepts it.

Not one of the thirty pull requests of `docs/tasks/absorb-plan.md`: the lead asked for it on 2026-11-21 ("do some design work for the cli TUI and make it as userfriendly and appealing as possible without discounting any functionalities or features, make everything accessible easily and usable without a hitch"). Lane: product. Effort: L in all. Read AGENTS.md, `docs/design/tui.md` in full, ADR 0044, ADR 0027 and ADR 0033 before starting any part.

Goal: A terminal interface, `engram tui`, that reaches every command, flag and feature of the `engram` CLI and the routes the inspector uses, teaches the plain command for every action, holds no policy logic, and leaves every existing plain output and exit code byte for byte as it is, but for HELP's first line, which names `engram tui`.

Why: The CLI is the main way a person meets the plane outside pi, and its forty-odd flags are hard to learn from `--help` alone. A TUI that shows the exact command for each action makes the CLI learnable without hiding it, and gives the inspector's views (lanes, explain, the item page, the timeline, grants) to people who work in a terminal.

Decided on 2026-11-22 under the lead's delegation (`docs/tasks/lead-decisions.md`, item 62; `docs/design/tui.md`, section 14): pi-tui 1.3.0 at the pi pin, only under `packages/cli/src/tui/` (ADR 0044 stays proposed until the lead accepts it, and the work proceeds on it); `engram tui` as the only entry, bare `engram` unchanged but for HELP's first line; the four new commands, then `scopes` and `read --item`; a new React-free `@engram/view` package for the shared view logic; the mouse on by default; the session's commands printed on quit unless `--quiet`.

Depends on:

- E9.8 (import and export) and E2.13 (who can read) merged before E8.15a, so the registry is written once with their commands in it.
- E8.14 (the framework kit) merged before E8.15a's `scopes` and `read --item <id>`; the rest of E8.15a does not wait for it.
- E8.12 (verified actors), merged into main on 2026-11-22 (`1ecf4aa9`): E8.15d's Serve, MCP and Keys screens are designed for it (`serve` and `mcp --http` refuse to start without a credential or `--insecure-loopback`; `engram key` needs `--keys`).
- ADR 0044: the work proceeds on it under the delegation above. If the lead later chooses Ink instead, only the render layer of E8.15b to E8.15e changes (ADR 0044, consequences).
- Commands of the cards still in flight (E8.13 export flags, E1.6 log verify, L6 supersede) enter through the registry when they merge; whichever part is open at the time adds their screen, and a later card adding a command adds its registry entry and nothing else.

## The five parts, in order

### E8.15a The registry and the plain CLI's additions

- `packages/cli/src/registry.ts`: one `CommandSpec` per command (`docs/design/tui.md` 6.1), with six groups and a `writes` function; `HELP` and the command table in `run.ts` built from it; the handlers' option objects read from it.
- Each plane command split into `prepare`, `call` and `print`, with the existing exported functions unchanged in behaviour, and `run`'s wrapping kept (card E8.13's `drainExports` in its `finally`).
- HELP's first line: `engram: the Engram control plane from the command line; engram tui opens the terminal interface`.
- "Did you mean" as a second stderr line for an unknown command or flag (12.2).
- `engram check`, `engram events`, `engram policy`, `engram grants`, each one client call, with tests per command as the existing commands have them, HELP lines, the README's command table and AGENTS.md's command list. After E8.14 merges: `engram scopes` and `engram read --item <id>` the same way.
- Files: `packages/cli/src/registry.ts` (new), `packages/cli/src/run.ts`, `packages/cli/src/commands.ts`, `packages/cli/test/registry.test.ts` (new), `packages/cli/test/<command>.test.ts` for each new command, `packages/cli/test/commands.test.ts` (the help snapshot: the first line and the new lines only), `packages/cli/README.md`, AGENTS.md and CLAUDE.md, `docs/log/`.
- Acceptance: `make test-one T=packages/cli/test/registry.test.ts`, and every existing file under `packages/cli/test/` passing unchanged except the help snapshot's first line and added lines.

### E8.15c Memory and audit screens, and `@engram/view`

- `@engram/view` (`packages/view/`, new): the code of `packages/ui/src/view.ts` and `provenance.ts` moved there with their tests, depending only on the generated client's types and on no React, xyflow, dagre or tanstack. Both old paths stay, each a one-line re-export of `@engram/view` (`export * from "@engram/view";` with a comment naming this card), as ADR 0033 kept `packages/runner/src/model/cached.ts`: immutable log entries cite those paths as evidence, and `make lint-docs` checks that every cited path exists. The inspector imports them from `@engram/view` with no change in behaviour (its unit and e2e tests pass unchanged), and `packages/cli/package.json` depends on `@engram/view`, never on `@engram/ui`, so the CLI's dependency graph gains no React.

### E8.15e Accessibility, line mode and the manual check

- Line mode (`packages/cli/src/tui/line.ts`, `node:readline` only, with `check`, mcp and hook as setup only, `quit` or end of input to leave, `ENGRAM_TUI_LINE=1`), high contrast, the light and dark palettes, ASCII detection, reduced motion, `--no-mouse`, the session's commands on quit, the screen-reader hint (section 11).
- The manual check on Windows Terminal, conhost (rendering the status glyphs, to decide whether its ASCII default can go), VS Code's integrated terminal, Git Bash in mintty, macOS Terminal and tmux, recorded in `docs/design/tui-manual-check.md` and a `finding` log entry; the `packages/cli/README.md` section on the TUI; a `make test-e2e` smoke that starts `engram tui` under a pseudoconsole if one is available on the CI image, else skipped with its reason.
- A pseudoconsole smoke of quitting with a running server (E8.15d review): `q` quits on the turn after its key (setImmediate), no render after the terminal is given back (the redraw guard), and the quit summary's write is guarded; start Serve, esc, `q`, then expect exit 0, no uncaught error and "stopped when the TUI quit" in the summary. The FakeTerminal cannot show these; only a real console does (the review's mutants of them survived).
- Files: `packages/cli/src/tui/`, `packages/cli/test/tui/`, `docs/design/tui-manual-check.md` (new), `packages/cli/README.md`, `docs/log/`.

## Tests required (`docs/conventions/testing.md`)

The layers of `docs/design/tui.md` section 13: registry, snapshot frames at 80x24 and 120x40 in four modes, keys, key flows, snippets, parity, refusals, line mode, no policy, saved workspace, redaction, and the manual check. ## Out of scope

- Any change to what the plane decides, to `packages/core`, to the schema (rule 5) or to the HTTP routes; the TUI calls what exists. A read-only preview of a retention sweep, which the read dialog would use for its count, is a backlog item for the plane, not this card.
- Colour or any other change in the plain CLI's output beyond the lines of 12.2.
- Authentication itself (card E8.12), the inspector's own pages (cards E8.5, E8.6, E8.11) and a web terminal.
- Editing policy files in the TUI; the Policy screen is read only.
- Running `engram mcp` over stdio or `engram hook` on the TUI's terminal (8.14, 8.15); Try it runs them as child processes on a scratch log.
- An `engram distill` command or a Procedures screen (8.25).
