# E8.15 The engram terminal interface

Status: design done on branch e8-15-tui-design, awaiting review (`docs/design/tui.md`, `docs/decisions/0044-cli-tui.md`); implementation open, in five pull requests, E8.15a to E8.15e.

Not one of the thirty pull requests of `docs/tasks/absorb-plan.md`: the lead asked for it on 2026-11-21 ("do some design work for the cli TUI and make it as userfriendly and appealing as possible without discounting any functionalities or features, make everything accessible easily and usable without a hitch"). Lane: product. Effort: L in all. Read AGENTS.md, `docs/design/tui.md` in full, ADR 0044, ADR 0027 and ADR 0033 before starting any part.

Goal: A terminal interface, `engram tui`, that reaches every command, flag and feature of the `engram` CLI and the routes the inspector uses, teaches the plain command for every action, holds no policy logic, and leaves every existing plain output and exit code byte for byte as it is.

Why: The CLI is the main way a person meets the plane outside pi, and its forty-odd flags are hard to learn from `--help` alone. A TUI that shows the exact command for each action makes the CLI learnable without hiding it, and gives the inspector's views (lanes, explain, the item page, the timeline, grants) to people who work in a terminal.

Depends on:

- ADR 0044 accepted (`docs/tasks/lead-decisions.md`, item 62), for E8.15b onwards. E8.15a does not need it.
- E9.8 (import and export) and E2.13 (who can read) merged before E8.15a, so the registry is written once with their commands in it.
- The lead's calls of `docs/design/tui.md` section 14. Items 1, 5 and 6 only change defaults. If item 2 (the four new commands) is declined, E8.15a drops them and E8.15c drops the four screens and the write preview; section 3.8 then lists them as not reachable.
- Commands of other cards in flight (E8.12 keys, E8.13 export flags, E1.6 log verify, L6 supersede) enter through the registry when they merge; whichever part is open at the time adds their screen, and a later card adding a command adds its registry entry and nothing else.

## The five parts, in order

### E8.15a The registry and the plain CLI's additions

- `packages/cli/src/registry.ts`: one `CommandSpec` per command (`docs/design/tui.md` 6.1); `HELP` and the command table in `run.ts` built from it; the handlers' option objects read from it.
- Each plane command split into `prepare`, `call` and `print`, with the existing exported functions unchanged in behaviour.
- "Did you mean" as a second stderr line for an unknown command or flag (12.2).
- If section 14 item 2 is accepted: `engram check`, `engram events`, `engram policy`, `engram grants`, each one client call, with tests per command as the existing commands have them, HELP lines, the README's command table and AGENTS.md's command list.
- Files: `packages/cli/src/registry.ts` (new), `packages/cli/src/run.ts`, `packages/cli/src/commands.ts`, `packages/cli/test/registry.test.ts` (new), `packages/cli/test/<command>.test.ts` for each new command, `packages/cli/test/commands.test.ts` (the help snapshot: new lines only), `packages/cli/README.md`, AGENTS.md and CLAUDE.md, `docs/log/`.
- Acceptance: `make test-one T=packages/cli/test/registry.test.ts`, and every existing file under `packages/cli/test/` passing unchanged except the help snapshot's added lines.

## Acceptance for the whole card

`make test-one T=packages/cli/test/tui/parity.test.ts` passing for every command in the registry (every flag reachable, every action the same client call as its plain command, plain and JSON views byte for byte), with every existing test under `packages/cli/test/` passing unchanged except the help snapshot's added lines.

## Tests required (`docs/conventions/testing.md`)

The layers of `docs/design/tui.md` section 13: registry, snapshot frames at 80x24 and 120x40 in four modes, key flows, parity, refusals, line mode, the biome import rule, redaction. Fakes only: the in-process app, the files adapter on temporary folders, an injected clock and ids; no network, no model. Write each part's test first and see it fail.

## Out of scope

- Any change to what the plane decides, to `packages/core`, to the schema (rule 5) or to the HTTP routes; the TUI calls what exists.
- Colour or any other change in the plain CLI's output beyond the lines of 12.2.
- Authentication (card E8.12), the inspector's own pages (cards E8.5, E8.6, E8.11) and a web terminal.
- Editing policy files in the TUI; the Policy screen is read only.
- Running `engram mcp` over stdio or `engram hook` from the TUI (8.14, 8.15).
