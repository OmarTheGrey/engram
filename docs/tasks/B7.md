# B7 MERIT through the plane and the proxy

Status: open.

From `docs/tasks/absorb-plan.md`, pull request 10 of 30 (research plans R-033 in `docs/research/absorb/long-list.md`). Lane: research. Week: W11. Effort: M. Read AGENTS.md, the plan's entry for this card and `docs/conventions/absorption.md` before starting.

Rewritten on 2026-11-21 by the absorb plan. Roadmap v1's card was "MERIT harness through the plane with cost accounting", files `bench/merit/`, acceptance "one task runs; cost recorded". Under ADR 0001 the paths are the TypeScript layout in AGENTS.md.

Goal: MERIT's harness runs as an external process whose model calls go through the cassette proxy and whose memory calls go through `Plane.read` and `Plane.write`, with the cost of every call recorded, and a fixture slice replays offline with zero new calls.

Why: H2's frontier is registered on GateMem, LongMemEval and MERIT, and MERIT is the one that measures whether a remembered fact leads to a correct action at a stated cost. The card has been open since roadmap v1.

Steps:

1. MERIT is pinned in `packages/bench/PINS.md` (MIT, commit `293933d`). Fetch it at the pin into `.engram/upstream`; nothing of it is committed beyond what the vendoring convention already allows.
2. A launcher that starts the proxy (card B10), then MERIT's harness with its model endpoint set to the proxy, and passes the item, condition and seed.
3. The memory seam: MERIT's memory interface mapped to the plane, under conditions C1, C2 and C5, each on the registered stores.
4. A fixture slice (a few seeded worlds) with committed cassettes; `make bench BENCH=merit` replays it. Cost comes from the usage ledger.
5. Check its scores on the slice against MERIT's own reference runs, and log any difference.
