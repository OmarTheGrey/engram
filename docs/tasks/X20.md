Goal: When the provider refuses an answer call with an error no retry can fix (a prompt over the context limit, a 400, a 403 that is a moderation flag), the runner records the session as excluded under its own reason, counted per condition, and goes on; an HTTP 401, 402, 403 (other than a moderation flag) or 404 at any model call, the judge's included, stops the run instead and is never recorded or a per-session exclusion, and so does a run in which five distinct items in a row each end in a refused answer call. A replay excludes the same sessions the same way with zero calls.

Why: Pre-tag condition 3 says items 14 and 15 are built before the tag, and the Statistics section says this one is not. Today a non-transient answer failure ends the run: `sessionFailure` in `packages/runner/src/model/cassette.ts` returns it and each probe throws it (`gatemem-probe.ts`, line 478), so one over-long prompt would stop a multi-day H1 run (item 14's reason). The 401, 402 and 403 rule is the coordinator's decision of 2026-11-21 (`docs/log/2026-11-21-answers-decision-cap-in-billed-dollars.md`): a key or credit problem is the operator's to fix, and excluding every later session under it would empty the run. The orchestrator's decisions of 2026-11-26 (`docs/log/2026-11-26-gwfix-decision-x20-stops.md`), from the cards' review, extend it: the judge's live path is in scope, since a 402 at GateMem's judge is today recorded as a failed attempt (`JudgeCallFailed`, `cachedJudgeCall`) and would empty the run the same way; a 404 stops, since a pinned endpoint that is gone (card R6, `allow_fallbacks: false`) or a bad model id fails every call; a 403 that OpenRouter documents as a moderation flag is a per-prompt refusal, so it is excluded; a run stops when five distinct items in a row each end in a refused answer call, a backstop for any other run-wide cause; it counts items, not sessions, since one item runs as consecutive sessions (`run.ts` loops item, then condition and store, then seed: 12 sessions per GateMem item under C2 to C5 at three seeds), and an over-long item is refused in all of them. The lead amended pre-tag condition 3 to this on 2026-11-26 ("Amend: 404 + backstop", `docs/tasks/lead-decisions.md`, "The lead's answers, 2026-11-26").
