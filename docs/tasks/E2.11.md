# E2.11 Trust floors in the write path and in retention

Status: open.

From `docs/tasks/absorb-plan.md`, pull request 20 of 30 (research plans R-023, R-024 in `docs/research/absorb/long-list.md`). Lane: research. Week: W13. Effort: M. Read AGENTS.md, the plan's entry for this card and `docs/conventions/absorption.md` before starting.

Goal: With the policy's trust options on: a write whose actor attests no source lands at the least trusted kind, and no write, eviction or retire by a less trusted source changes or removes a more trusted active item unless its owner acts. With them off, nothing changes.

Why: This is the fix for whatever card E2.7 confirms. If a caller with no attested source can claim to be a person typing, the provenance model the thesis rests on has a hole. If an agent's write can evict or overwrite a person's item, source isolation is weaker than ADR 0007 says.

Steps:

1. Start from E2.7's findings. A gap it refuted is dropped from this card. E2.7 confirmed both gaps, and they reach further than first reported:
   - **Wider scope.** They reach team scope under every registered preset (`docs/log/2026-11-21-e2-7-finding-gh-38-every-preset.md`).
   - **More consumers.** They reach the confirmations promotion counts and the retired-content rule (`docs/log/2026-11-21-e2-7-finding-gh-39-promotion-and-relearning.md`). Both read the claimed provenance kind, so the floor must apply before either is consulted.
   - **Adoption.** Adopting a hand-edited store record of a `user` item records it as `import`. ADR 0040's exemption covers only the owner acting as `user`, so this card decides how adoption is treated and records it in a `decision` entry.

   E2.7's characterisation tests in `packages/core/test/counterexamples/trust.test.ts` are the cases to flip.
2. The floor (`trust.unattested_floor`): in `withPlaneProvenance`, an actor with no source gets the least trusted kind and a reason, instead of the caller's claim. The CLI, the MCP server, the Claude Code hook and the pi extension already set a source, so the floor reaches library callers and HTTP clients that send none.
3. The stated limit: on the HTTP API the source is self-asserted, as the actor id is (ADR 0027), so a client that sends `source: user` is believed. The floor does not close that. Verified actors do (card E8.12), and until then the limit is written into `docs/architecture.md` beside the existing one.
4. Protection (`trust.protect_trusted`): `evaluateWrite` denies a rewrite or retire of a more trusted active item by a less trusted source with reason `engram/write/downgrade`, and the retention victim order never evicts a kind more trusted than the writer that triggered the eviction. The owner acting as a user is exempt.
5. Both off in the H1 to H4 presets, so no registered number moves, and on in a new preset. A test asserts each registered preset's decisions are byte-identical.
6. The eighth invariant in the always-on file, with the oracle extended. Each of E2.7's characterisation tests gains its counterpart under the options: the same case, now denied or floored. The invariants file changes only with a second reviewer (`docs/conventions/testing.md`).

- Veracium (MIT, port): the unattested-write floor design.
