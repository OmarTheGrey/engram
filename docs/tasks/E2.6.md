# E2.6 Every store-then-log commit holds under the log's lock, so no writer on another handle undoes an erasure

Status: done on branch e2-6, awaiting review. Paths: the protocol is `packages/core/src/plane/commit.ts`, used by `packages/core/src/plane/write.ts` (Plane.write and adoption's `adoptWrite`), `grants.ts`, `promote.ts`, `offboard.ts` (the erasure mark and the handover), `adopt.ts` and `retention.ts`; ADR 0007's amendment of 2026-11-19 (with notes in ADR 0010 and ADR 0034); the tests are `packages/core/test/unit/plane/cross-handle.test.ts`, `packages/adapters/test/plane/cross-handle-files.test.ts` and invariant 1's two-handle walk in `packages/core/test/property/invariants.test.ts`. Created 2026-11-19 by the orchestrating session from the verification of PR #44 (card E9.4).

From the verification of PR #44 and `docs/tasks/backlog.md` (follow-ups from card E9.4), epic E2. Read AGENTS.md, `docs/architecture.md` and ADRs 0007, 0010, 0021, 0024 and 0034 before starting.

Goal: For every operation that writes the store and then appends to the log, against a writer or an offboarding on another db handle over the same log, in every ordering: an erased item never returns (not in the projection, a rebuild, the store or a read); a committed decision (a grant change, a removal, a handover, a promotion) is never silently undone; a decision taken on a stale projection is refused with a deny event that carries a reason and a policy id, and the store is put back to match the projection.

Files: packages/core/src/plane/ (write, offboard, promote, retain, adopt, grants as needed) and their tests, packages/adapters/test/plane/ (a files-adapter case), ADR 0007's amendment, docs/architecture.md, this card, docs/tasks/backlog.md, the log. The invariants file (packages/core/test/property/invariants.test.ts) is lead-owned: a change there may only strengthen it, with a `decision` log entry.

Depends on: E2.2, E9.7

Acceptance: every reproduction R1 to R9 of the verification of PR #44, and the retain, adoption and grant-change orderings, is a committed test that fails on main before the fix and passes after; `make test-invariants` includes a two-handle property (a random interleaving of two handles' operations, offboarding included, never returns erased content to any reader); `make test`, `make test-e2e` and `make api-check` pass.

Out of scope: authentication (ADR 0027), the read path beyond what a fix needs, the UI; schema changes (AGENTS.md rule 5).
