# X23 The request-identity check: every model request the same on files, Mem0 and Letta

Status: planned, gate work (2026-11-25). Gate D's "two stores" criterion (ADR 0035, decisions 1 and 3).

From `docs/tasks/absorb-plan-2.md`, section 9, "Gate work cards (2026-11-25)". Lane: research. Week: W11 (14 to 20 December), after H1's `MERGE=4`, so card A6 (W12) can add its store to the check. Effort: M. Read AGENTS.md, ADR 0035, ADR 0031 (decision 2), ADR 0013, `docs/conventions/testing.md` and card B3 before starting.

Goal: A rule-9 result, `research/results/h4-request-identity.json`, from a script that replays one GateMem configuration under C2 to C5 on the files, Mem0 and Letta stores offline, records the sha256 of every model request per (item, condition, seed, call), and fails if any request differs between stores.

Why: ADR 0035 makes store independence a property of the design, proven rather than tested: no condition uses a store's own search (ADR 0031, decision 2), so the model's requests cannot depend on the store. Decision 1 asks for the check as a rule-9 result with a MANIFEST row; decision 3 makes it how Gate D's "two stores" is met; the pre-registration's H4 Stopping rule names it and says it needs the files store in the runner, whose stores are fake, Mem0 and Letta today (`packages/runner/src/stores.ts`, line 23). No card file exists for it (backlog row "The request-identity check").
