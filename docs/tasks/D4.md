# D4 Drift: re-validation and retirement of admitted procedures

Status: planned, absorb plan 2.

Rewritten on 2026-11-25 by `docs/tasks/absorb-plan-2.md`, pull request 19 of 30 (research plan R-021's drift half in `docs/research/absorb/long-list.md`). The roadmap's v1 text was: "Drift detection: periodic re-validation; retire below threshold (kill list item 1)"; its acceptance is kept. Lane: research. Week: W13. Effort: M. Read AGENTS.md, the plan's entry for this card, ADRs 0011, 0026 and 0046, and `docs/conventions/absorption.md` before starting.

Goal: Re-run an admitted procedure's replay on its held-out tasks when its environment hash changes or a period passes (`procedures.drift`), seeded and cached like card D3's, and retire it by a governed event when it falls below the admission rule, keeping the retired version for rollback.

Why: Ungoverned skill libraries drift below the no-skill floor and retirement recovers them (Library Drift, 2605.19576). The `replay-drift` and `environment-changed` triggers exist in `packages/core/src/lint.ts` with no producer, and crosswalk claim C48 waits for this card. Card D3 is merged, so nothing blocks it.

Steps:

1. A fixture with a changed task first: an admitted procedure whose replay now fails.
2. `packages/core/src/distill/drift.ts`: when to re-validate (environment hash change, or the period from the policy), using D3's rule unchanged (5 held-out tasks, seeds 1 to 3, 2/3, 4 of 5).
3. The runner's replay validator reused; every call seeded and cached (rules 6 and 7).
4. Retirement through `Plane.retain` or a governed retire event naming the trigger; the retired version kept and restorable.
5. Lift the `procedures.drift` refusal in `policy/load.ts` (absent means off, today's behaviour) with a loader test.
6. Crosswalk claim C48 pointed at the new test, moving the unregistered `research/results/h1-crosswalk.json` row in this PR with `make test-repro` on it and a measurement entry.

Absorbs (mode per ADR 0037):

- SkillGuard drift (2605.10990), Library Drift (2605.19576) and SKILL.nb's rollback of retired skills (2606.08049): papers, idea.

Files: packages/core/src/distill/drift.ts (new), packages/core/test/unit/distill/drift.test.ts (new), packages/core/src/distill/validate.ts, packages/core/src/policy/load.ts, packages/runner/src/replay-validate.ts, fixtures/sessions/, fixtures/cassettes/ (new, scripted), research/configs/crosswalk.json and the `h1-crosswalk.json` row, docs/log/

Acceptance: `make test-one T=packages/core/test/unit/distill/drift.test.ts`: a fixture with a changed task retires the skill, replayed from cassettes with zero new calls

Risks: H5 registers admission, not retirement: drift is off in H5's configs, and reported, if ever, only as an engineering check or a proposed arm.

Guard: D3's fixtures and cassettes, and every registered result, stay byte for byte as they are; only the unregistered crosswalk row moves, as step 6 says. Nothing here changes a registered condition, preset or config.
