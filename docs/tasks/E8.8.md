# E8.8 Approvals on every surface and the inspector's queue

Status: planned, absorb plan 2.

Rewritten on 2026-11-25 by `docs/tasks/absorb-plan-2.md`, pull request 27 of 30 (research plans R-079 and R-080 in `docs/research/absorb/long-list.md`). The roadmap's v1 text was: "Review queue for candidates and promotions", acceptance "approve promotes; reject retires", which is kept. Lane: product. Week: W14. Effort: L. Read AGENTS.md, the plan's entry for this card, ADRs 0026, 0027 and 0042, and card E2.19 before starting.

Goal: The approval queue of card E2.19 on every surface: routes, `engram review list|approve|reject`, MCP tools, and the inspector's queue screen showing each request's item, routing and expiry. Approve promotes; reject retires. The inspector holds a credential so it can call an authenticated server.

Why: Govern's review is the card the first plan's section 7 relied on, and it was never built. Gate D's Knowledge dogfood needs someone to see the queue. Card E8.12's finding: the inspector has no way to call a server that requires a credential.

Steps:

1. A Playwright test first: approve writes a promote event, reject a retire event, an expired request shows as expired.
2. Routes over E2.19's projection and decisions; `make api`.
3. The CLI commands through the generated client; MCP tools for the same.
4. The inspector's queue screen, filtered by what the viewer may read.
5. A credential for the inspector (a key it is given at `engram serve` time), never stored in the page.
6. A `finding` for branch `cliupgrade` naming the new commands.

Absorbs (mode per ADR 0037):

- Nothing beyond the inspector's existing dependencies.

Files: packages/server/src/routes.ts, packages/cli/src/commands.ts, packages/mcp/src/server.ts, packages/ui/src/, sdk/ and packages/ui/src/api/ (generated), AGENTS.md and CLAUDE.md, docs/log/

Depends on: E2.19; E2.5 and E8.5 are merged

Decision: none.

Acceptance: `make api-check` and `make test-e2e`, with the queue's Playwright test

Risks: Leaking a request's item to a viewer who may not read it; the screen uses the read matrix as every other screen does.

Guard: Surfaces only. Every MANIFEST row, fixture and cassette stays byte for byte as it is. Nothing here changes a registered condition, preset or config.

Out of scope: anything in another package beyond the files above; any `schema_version` bump; schema changes unless the card says so (AGENTS.md rule 5)
