Goal: `Plane.lint` judges which items a finding may name or describe through the read filter a read uses (`evaluateRead`), not through `readableAt`, which checks only scope or grant.

Why: Today `canReach` in `packages/core/src/plane/lint.ts` is `readableAt`. A finding may then name or describe a candidate, a retired item, an item past its ttl reached by a live grant, or an item not yet valid: items Plane.read refuses the same member.

Steps:

1. Find every registered path that calls `Plane.lint` or `planModelLints` (the H3 fault set's label check, the H3 lint floor, the near-duplicate pairs, the NLI tier runs, the cost table's counts) and whether its inputs hold items the read filter refuses.
2. Write the counterexamples first: a lint as a member names or describes none of a candidate it may not read, a retired item, an expired grant's item, a not-yet-valid item. Each finding stays one lint event with its reason (rule 3).
3. Implement, then rerun every reachable MANIFEST row's script and the H3, L2, L3 and L4 tests, and compare the bytes.
4. If no committed byte moves, the filtered reach is the only behaviour. If some byte moves, nothing is regenerated: the filtered reach is the default of every product surface (the CLI `engram lint`, the server's lint route, and the MCP server and pi extension if they lint), and core gains an explicit, named option the registered research call sites pass to keep their registered reach.
5. A `decision` entry records which case applied, with its evidence; in the second case a `finding` names what would change after the `prereg-v1` tag.
