Goal: A near-duplicate lint finds near-duplicates without embeddings: word-shingle MinHash for candidates and a precision tier that vetoes pairs whose rare terms, numbers or polarity differ. It runs only when a policy enables it by its own lint id, which no registered preset does, so every committed result is byte-identical.

Why: ADR 0018 names a MinHash near-duplicate lint and card L1 built only the exact one. On LongMemEval's own memory the exact-duplicate lint is the only deterministic lint that fires (967 findings in `research/results/h3-lint-floor.json`), so a near-duplicate tier is the cheapest way to give H3's deterministic floor more to say.

Steps:

1. A deterministic lint of its own id, `near-duplicate-tier`, added to `DETERMINISTIC_LINT_IDS` in `packages/core/src/lint.ts`, beside `duplicates()` in `packages/core/src/lint/det.ts`: MinHash with a fixed seed over word shingles, with character shingles below a length floor. It runs only when a policy lists `near-duplicate-tier` in `lints.enabled`. The threshold is not the switch: strict, medium and permissive already set `lints.thresholds.near-duplicate` (0.8, 0.85 and 0.9) though no code reads it today, so a switch on the threshold would turn the tier on in every registered preset. The new lint reads its similarity from that key. The id cannot be `near-duplicate` itself, since `policy/load.ts` refuses a lint id that is a threshold key. Lint ids are strings in the schema, so no schema change is needed; if `make api-check` shows otherwise, the id goes through card E2.8's schema PR. The `duplicate` lint stays exact-only. The finding carries the estimated Jaccard similarity.
2. The precision tier: IDF-weighted cosine over the scope's items, with a veto when the highest-IDF terms of the two items differ, and a veto on differing numbers and on opposite polarity.
3. A research script checks precision and recall on the fault catalogue against datasketch as an oracle, on the research side only.
4. A test that every registered preset's `duplicate` findings, and its whole lint report, are byte-identical with the card merged, on the fault catalogue and on card L2's base, and `make test-repro` showing no committed hash moved.

Absorbs (mode per ADR 0037):

- claude-mem (Apache-2.0, port): the IDF cosine and IDF veto (`nearDuplicate.ts`, `idf.ts`, `idfVeto.ts`).
- codebase-memory-mcp (MIT, port): the MinHash layout; its parameters are re-derived, not trusted.
- hermes-dreaming (MIT, idea): the veto on differing numbers, names and polarity.
- obsidian-mind (MIT, idea): title-weighted Jaccard as a comparison point.
- datasketch (MIT, idea): the oracle, in research code only.

Risks: ADR 0018 forbids embeddings by default: none are used. A pairwise pass is quadratic; banding keeps it near linear and the test measures it at 10,000 items. As built (review finding L5-4), banding is near linear on varied text, and a cap of 64 estimates per item keeps templated text linear at the cost of completeness; the tests measure 10,000 varied items and 4,000 templated ones.

Out of scope: enabling `near-duplicate-tier` in any registered preset, or making the threshold key a switch; write-time deduplication beyond the exact hash; merging duplicates (the lint reports, a person decides); anything in another package; schema changes unless the card says so (AGENTS.md rule 5)
