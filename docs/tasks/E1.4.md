# E1.4 A stateful model-based test of the Plane, with crash windows

Goal: Generated sequences of every Plane operation are checked against the oracle after each step and shrink to a minimal failing sequence with its seed; and each window between "the store was written" and "the event was appended" has a deterministic test that fails there and shows recovery.

Why: The seven invariants are checked over generated single operations and one two-handle walk. Failures come from sequences. Card E2.6 needed five review rounds, each finding a narrower race that a reader had to think of.

Steps:

1. `stateful.test.ts`: a fast-check command model (`fc.commands`) over write, read, grant change, promote, retain, offboard, adopt, handle reopen and clock advance, on the real Plane with the fake adapter and the injected clock. After every command, assert `oracle.ts` and the existing invariants. The seed and path are printed on failure.
2. A vacuity check: a deliberately broken Plane wrapper that the model must catch.
3. `failpoint.ts` in the test tree: wraps the Db and adapter fakes and fails, or stops, at a named step. Core's source is not touched.
4. `crash-windows.test.ts`: one case per window in the write, offboard and adapter-delete paths, each showing what the next handle sees and that recovery completes.
5. Add the stateful file to `make test-invariants`. A window that does not recover is a `finding` with its seed, not a fix in this card: its case is written as a plain test asserting what happens today, with the finding id in its name, so the gate stays green and the gap stays pinned. A failing sequence the stateful test finds is handled the same way, as a pinned regression case, and reported to the lead before the tag.

Absorbs (mode per ADR 0037):

- fast-check (MIT, depend): `fc.commands`, already a dependency (4.10.2).
- EverOS (Apache-2.0, port): the failpoint design of `core/failpoints.py`: fail, pause or skip at a named step (about 60 lines, rewritten in TypeScript).
- metronix-memory, mnemonic (Apache-2.0, idea): which crash windows and recovery states to cover.
