# E2.8 Policy schema: content guards and trust floors

Status: open.

From `docs/tasks/absorb-plan.md`, pull request 13 of 30 (research plans R-026 and the schema halves of R-023 and R-024 in `docs/research/absorb/long-list.md`). Lane: research. Week: W11. Effort: S. Read AGENTS.md, the plan's entry for this card and `docs/conventions/absorption.md` before starting.

Goal: One schema-only pull request adds the policy options cards E2.9, E2.10 and E2.11 need, all defaulting to today's behaviour.

Why: Rule 5 puts every schema change in a pull request of its own. Three cards each need one option; one schema change is cheaper and safer than three.

Steps:

1. In `packages/core/src/schema.ts`, the policy gains a `content_guards` block (`secrets` and `pii`, each off, review or block; `injection_screen` off, default or hardened; `max_content_bytes`) and a `trust` block (`unattested_floor`, off or on; `protect_trusted`, off or on). The names are settled in ADRs 0039 and 0040.
2. Every default is off, so a policy file without the blocks behaves as it does today, and the H1 to H4 presets are untouched.
3. Bump `schema_version`, add the migration, run `make api`, update the fixtures.
4. A test that each registered preset evaluates byte for byte as before.
