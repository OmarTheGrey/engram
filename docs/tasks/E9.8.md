# E9.8 Memory import and export

Status: open.

From `docs/tasks/absorb-plan.md`, pull request 26 of 30 (research plans R-043 in `docs/research/absorb/long-list.md`). Lane: product. Week: W15. Effort: M. Read AGENTS.md, the plan's entry for this card and `docs/conventions/absorption.md` before starting.

Goal: `engram export` writes the memories an actor owns to a portable bundle with their provenance, validity and decisions, and `engram import` brings a bundle or a pasted memory list in as governed writes that start as candidates.

Why: A person's memory should not be locked into Engram, and a new user arrives with memories somewhere else. Portability is also what Article 20 of the GDPR asks for.

Steps:

1. The bundle: JSONL, one item per line with provenance, validity window, lineage and its decision events, limited to scopes the actor owns and filtered by the read matrix. The format is versioned and documented.
2. Import: every row is a `Plane.write` by a dedicated import actor with provenance kind `import`, status `candidate`, grants dropped, so the gate decides and nothing arrives trusted.
3. A round-trip invariant: export, import into an empty workspace, promote, export again; the content, validity and lineage are equal.
4. A parser for the memory list Claude shows a user, pasted as text. A ChatGPT parser only once a real export is seen to contain memories; otherwise it is left out and the log says why.
5. Optional encryption of a bundle with age, by passphrase or recipient key.

Absorbs (mode per ADR 0037):

- typage (BSD-3-Clause, depend): `age-encryption`, pinned exactly (it is before 1.0), for the optional encrypted bundle.
- memfix (MIT, idea): importer mappings and the shape of an adoption report.

Files: packages/cli/src/commands.ts, packages/cli/src/import/ (new), packages/cli/test/, fixtures/ (synthetic bundles), docs/ (the bundle format), AGENTS.md and CLAUDE.md, docs/deps.md, docs/log/

Depends on: none

Acceptance: the round-trip test, and a `make test-e2e` smoke of export then import

Risks: The CLI's write sets source `user` today: the import actor must not inherit it. Synthetic fixtures only (rule 12).

Out of scope: importing from another store's database; a sync service; importing grants; anything in another package; schema changes unless the card says so (AGENTS.md rule 5)
