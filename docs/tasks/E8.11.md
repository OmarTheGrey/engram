# E8.11 Inspector: the provenance graph, the event table, the version diff

Status: open.

From `docs/tasks/absorb-plan.md`, pull request 25 of 30 (research plans R-039 in `docs/research/absorb/long-list.md`). Lane: product. Week: W15. Effort: M. Read AGENTS.md, the plan's entry for this card and `docs/conventions/absorption.md` before starting.

Goal: An item's page in the inspector shows its lineage and the decisions about it as a graph, the log as a sortable table that stays fast at tens of thousands of events, and the difference between two versions as a text diff.

Why: The inspector explains a read in text. Lineage is a graph, a log is a table, and a rewrite is a diff. These are the three screens that make "every recall can be explained" visible in a demonstration.

Steps:

1. The graph: the item, its lineage and its decision events as nodes, laid out with dagre, from data the server already returns for the viewer. A new route only if a field is missing, with `make api`.
2. The table: every event the viewer may see, virtualised, sortable and filterable by type, actor and scope.
3. The diff: two versions of an item side by side, with the event that made the change.
4. A leak test in Chromium: for a viewer who cannot read an ancestor, the graph has no node, no edge and no count that reveals it.
5. Keyboard access and both colour schemes, as the rest of the inspector.

Absorbs (mode per ADR 0037):

- xyflow (MIT, depend): `@xyflow/react`, pinned at 12.12.1.
- dagre (MIT, depend): graph layout; elkjs is EPL or GPL and is not used.
- TanStack Table and Virtual (MIT, depend): the event table.
- jsdiff (BSD-3-Clause, depend): the text diff.

Files: packages/ui/src/, test/e2e/, fixtures/workspaces/inspector/, packages/server/src/routes.ts and sdk/ only if a route is needed, docs/deps.md, docs/log/

Depends on: E8.5 (merged). Card E8.10 (the diff between two snapshots of a scope, open) is a different screen that can share the diff component: whichever lands second reuses it

Decision: none.

Acceptance: `make test-e2e`, including the leak test

Risks: A hidden ancestor leaking through a dangling edge or a count. Bundle size: the graph library is loaded only on the item page.

Out of scope: editing from the graph; policy logic in the inspector (rule 1); anything in another package; schema changes unless the card says so (AGENTS.md rule 5)
