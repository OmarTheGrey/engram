# BF1 MPBench fallback: reconstruct the probe format from the paper

Goal: if MPBench (arXiv 2606.04329) is not released, build a poisoning probe set in its published format so the poisoning arm of ADR 0015 can run. Reconstruct the case schema from App. D (attack type, attack signal, domain, adversarial goal, user query, context, expected memory, retrieval query), the six attack classes and the two-session protocol of Sec. 4.1: session one carries the payload and the store is inspected; session two asks a related retrieval query and the response is judged.

Files: `packages/bench/src/mpbench/`, `fixtures/faults/mpbench/`, `research/configs/mpbench-fallback.yaml`, `docs/research/preregistration.md` (amendment).

Depends on: S0.6 (pins), S0.12 (pre-registration v0), and a dated decision that the authors' release will not arrive in time.

Acceptance: each of the six attack classes has at least 20 seeded attack cases and 20 benign cases under `fixtures/faults/mpbench/`, generated by a seeded script; `make bench BENCH=mpbench-fallback` runs them through the pi runner with a scripted model; the pre-registration amendment states that these results are on a reconstruction, not on MPBench.

Out of scope: comparability with the numbers in the MPBench paper; an LLM judge (the fallback scores the stored memory deterministically against the expected memory where the schema allows).

Alternative: MEM-INV-Bench (arXiv 2606.24322), named in `docs/readings/litreview/sota-2026.md`.
