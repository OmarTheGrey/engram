# E2.12 Policy exported to Cedar, with a differential test

Goal: `exportCedar(policy)` turns an Engram policy into a Cedar schema and policy set, and a property test shows the Cedar engine and Engram's evaluator agree on every generated request for the three presets.

Why: Cedar has what the typed policy lacks: a formal semantics and an analyser. Agreement on every generated case is an independent check of the evaluator, and a route to statements such as "strict never allows a read that medium denies".

Steps:

1. A pure `exportCedar` in core: scopes, memberships and the read and write matrices as Cedar entities and policies. No runtime dependency: the function returns text.
2. The differential test: generated actors, items and times, each decided by `evaluateRead` and `evaluateWrite` and by the Cedar engine on the export, for strict, medium and permissive.
3. Grants are flattened at export, so agreement holds modulo grants. The test states which requests it excludes and why.
4. A disagreement is a `finding` with its seed. The evaluator is changed only by its own card; this card changes the export or records the difference.
