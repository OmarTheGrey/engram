# E8.13 Decisions exported as OpenTelemetry spans

Status: done in PR #95 (merged 2026-11-22). Paths: packages/core/src/export/otel.ts, packages/core/test/unit/export/otel.test.ts, packages/core/src/events.ts (eventsAfter, lastSeq), packages/server/src/export.ts, packages/server/src/app.ts, packages/server/test/export.test.ts, packages/cli/src/ (commands.ts, connect.ts, run.ts, serve.ts, hook.ts), packages/cli/test/export.test.ts, docs/decisions/0043-decision-export-egress.md.

From `docs/tasks/absorb-plan.md`, pull request 29 of 30 (research plans R-138 in `docs/research/absorb/long-list.md`). Lane: product. Week: W17. Effort: M. Read AGENTS.md, the plan's entry for this card and `docs/conventions/absorption.md` before starting.

Goal: Each policy decision can be exported as an OpenTelemetry span, off by default, carrying the decision, the rule and the actor, and never the memory's content.

Why: An organisation that adopts Engram already has an observability stack. Decisions that appear there beside the model calls they governed need no new tool to audit.

Steps:

1. A pure mapping in core from a MemoryEvent to a span's name and attributes, following the GenAI semantic conventions at a pinned version.
2. A test over every event type asserting that no attribute holds content, a content hash that could be reversed by lookup, or a path inside a store.
3. Two sinks in the CLI and server, both off unless configured: OTLP over HTTP, and a JSONL file. No webhook.
4. A short ADR on egress: what leaves the machine, that it is opt-in, and how rule 12 is kept.

Absorbs (mode per ADR 0037):

- OpenTelemetry JavaScript (Apache-2.0, depend): `@opentelemetry/api`, `sdk-trace-base` and the OTLP HTTP exporter, each pinned exactly.
- OpenTelemetry GenAI conventions (specification, idea): the attribute names.

Files: packages/core/src/export/otel.ts (new), packages/core/test/unit/export/ (new), packages/cli/src/, packages/server/src/, docs/decisions/ (the egress ADR), docs/deps.md, AGENTS.md and CLAUDE.md, docs/log/

Depends on: none

Acceptance: the mapping test with the content-free assertion, and `make test`

Risks: Content leaking into a span through a reason string: reasons are checked by the same test. Arize Phoenix is under the Elastic licence and is not used.

Out of scope: a dashboard; metrics; tracing of model calls (pi and the harnesses own that); anything in another package; schema changes unless the card says so (AGENTS.md rule 5)
