# X15 Plane overhead: a latency budget measured against bare SQLite

Status: open.

From `docs/tasks/absorb-plan.md`, pull request 7 of 30 (research plans R-009 in `docs/research/absorb/long-list.md`). Lane: research. Week: W9. Effort: M. Read AGENTS.md, the plan's entry for this card and `docs/conventions/absorption.md` before starting.

Goal: A measured answer to what the plane costs in time: p50, p99 and p99.9 of `Plane.write` and `Plane.read` across store sizes and the three presets, beside a bare `node:sqlite` baseline, with the queries per call counted, as a rule-9 result and a published budget.

Why: The thesis measures the governance tax in utility. A reader and any adopter will ask for the other tax. It has never been measured.

Steps:

1. A benchmark suite under `packages/core/bench/` using tinybench, on the files adapter and the fake, at store sizes of 100, 1,000, 10,000 and 100,000 items, per preset.
2. Count queries with a wrapper around `Db.prepare`; the count is deterministic and is asserted exactly.
3. The suite writes raw samples to a JSONL file. The committed result is computed by `perf_budget.py` from the committed samples, so it is byte-stable under `make test-repro`. A separate check reruns the suite and passes when the new medians fall inside a stated tolerance band.
4. The result states the hardware, the Node version and the repeats. The budget (for example, a read at 10,000 items within some multiple of the baseline) is proposed from the measurement and written into `docs/architecture.md`.

Absorbs (mode per ADR 0037):

- tinybench (MIT, depend): a development dependency, pinned to an exact version at least two weeks old.
- graphCTX (MIT, idea): publishing a p95 latency budget and testing against it.

Files: packages/core/bench/ (new), research/scripts/perf_budget.py (new), research/configs/perf-budget.json (new), research/results/perf-budget.json and its samples file (new), research/results/MANIFEST.md, Makefile, AGENTS.md and CLAUDE.md, docs/deps.md, docs/architecture.md (the budget), docs/log/

Depends on: none

Acceptance: `make test-repro` regenerates the result byte for byte from the samples; the rerun check passes inside the tolerance band

Risks: Machine noise: report the hardware and the repeats, and never compare across machines. The MANIFEST row needs the follow-up PR that names the squash commit.

Out of scope: any optimisation of the plane (a slow path found here is a finding and a backlog row); anything in another package; schema changes unless the card says so (AGENTS.md rule 5)
