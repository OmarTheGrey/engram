# E8.12 Verified actors

Status: open.

From `docs/tasks/absorb-plan.md`, pull request 28 of 30 (research plans R-081 in `docs/research/absorb/long-list.md`). Lane: product. Week: W17. Effort: L. Read AGENTS.md, the plan's entry for this card and `docs/conventions/absorption.md` before starting.

Goal: The HTTP API and the HTTP MCP server know who is calling: a bearer token from a configured issuer or a local API key is mapped to an actor, and an unauthenticated call is refused unless the operator explicitly allows it on loopback.

Why: Every surface takes `--as` on trust, and `docs/architecture.md` lists it as a limit. A governance product whose actors are self-asserted cannot be deployed beyond one laptop.

Steps:

1. An ADR first, amending ADR 0027: how a token's issuer and subject map to an actor id and to the actor's source, that a token's claims never widen a grant or a membership, and that on an authenticated call a source sent in the request body is ignored (this closes the limit ADR 0040 states).
2. `engram serve` and `engram mcp --http` as an OAuth 2.1 resource server: audience-bound JWTs verified against the issuer's keys, and the protected-resource metadata of RFC 9728.
3. Local API keys: prefixed, stored hashed, shown masked, with expiry, compared in constant time.
4. Loopback without a token only behind `--insecure-loopback`. stdio keeps `--as`. `engram doctor` refuses a non-loopback bind without authentication.
5. An invariant: every event written through the HTTP surfaces names an actor that was authenticated, or the flag that waived it. The fact is recorded in a side table keyed by event sequence number, created in `packages/core/src/db/migrate.ts`, so the event schema does not change. If the ADR decides it belongs in the event, that is a schema PR of its own first (rule 5).

Absorbs (mode per ADR 0037):

- jose (MIT, depend): JWT verification, pinned at 6.2.17.
- TencentDB-Agent-Memory (MIT, copy): `user-key.ts` and `crypto.ts`: prefixed keys, masking and expiry.
- walrus-memory, Remnic (Apache-2.0, MIT, idea): signed requests and per-token namespaces.

Decision: item 54 of `docs/tasks/lead-decisions.md`, answered (a) on 2026-11-21 under the lead's delegation: an external issuer and local API keys, no bundled identity provider.

Acceptance: the invariant's test, the existing surface tests, and `make test-e2e`

Risks: H4 measures the current MCP surface: stdio and the registered harness fixtures do not change. No identity provider is bundled.

Out of scope: an identity provider, sign-up or sessions; role mapping from token claims; non-loopback serving by default; anything in another package; schema changes unless the card says so (AGENTS.md rule 5)
