Goal: a person alone can make a candidate in their own person scope active, by accepting it as its owner, user-sourced; every other promotion keeps ADR 0026's reviewer rule.

Why: An import writes every row as a candidate (card E9.8), and the injection screen holds what a person did not type as a candidate (card E2.10). In a person scope only a reviewer who is not the owner could promote one, so a person alone could never read their own imported memories, nor release a hold on their own agent's note. A person scope is the owner's own: accepting there authorises nothing for anyone else.

Steps:

1. ADR 0049, amending ADR 0026: who may accept, where the rule does not apply, trust, the injection screen's holds, the event.
2. The evaluator (`packages/core/src/policy/promotion.ts`): in a person scope only, the scope's owner, acting under their own id and level with source `user` and asking to review, may accept a candidate of that scope in place. One promote event under `engram/promote/owner-person` whose reason names the rule ("owner accepts in own person scope") and, for a held item, the hold. The same ask by the owner's agent (any other source) is refused under `engram/promote/reviewer`, with a reason that names the rule.
3. Trust is never raised: the in-place transition changes only the status and the version, so the provenance kind and the confidence stay the plane's.
4. The invariants' oracle (`packages/core/src/oracle.ts`, `promotionPermitted`) judges the rule with its own code, and invariant 2 draws owner acceptances with a guard that requires a landing and the refusals around it. The dogfood report knows the new rule id.
5. Tests first, mutation-checked: core (evaluator, the real plane), the oracle, the dogfood report, the CLI (`engram promote --review`, the import round trip) and the server's promote route. The MCP server and the pi extension expose no promotion.

Risks: Self-approval is what ADR 0026 rejected (2609.01836). The rule is held to the one scope where the owner's approval reaches no one else, to a user-sourced actor, and to a status-only change. No registered condition, fixture or result may move: none promotes in a person scope by its owner, and the card proves the bytes unchanged.

Out of scope: an episodic candidate (its promotion is a class change to semantic, which stays ADR 0026's corroboration or independent review, crosswalk claim C46); a procedural candidate (replay validation, which a review cannot replace); any promotion out of the person scope; shared scopes; the TUI on branch `cliupgrade`; schema changes (AGENTS.md rule 5).
