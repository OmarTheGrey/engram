**What.** C4's system prompt is C3's (the policy as text) plus a `<memory-metadata>` block: one constant legend per benchmark naming each attribute, then "decide from this metadata". MEM-INV-Bench's legend describes each channel factually (a public web feed, the ERP vendor registry) and calls none trusted or untrusted.

**Why.** "Instruction with metadata" needs the instruction and needs the model told what the attributes mean; constant text keeps every item's cache key stable. The paper's trust labels would be a judgement the model is meant to make.

**Result.** `conditions.test.ts` holds C4's prompt to C3's plus the legend, byte for byte apart from the working directory.

**Consequence.** The legends are protocol: changing one changes every C4 cassette key.
