**What.** Adding the proposals is not a new version of the pre-registration, so no row was added to its Versions table. Instead, registering an arm adds the row.

**Why.** Card R2 may edit only the proposals section, and the Versions table is a registered section. A proposal changes nothing that is registered, so the version stays the one the answers card wrote.

**Result.** The section's head says so: a registration moves the arm's text into the registered sections and adds the Versions row.

**Consequence.** If the lead wants the batch recorded as a version, one row is added in a follow-up. Nothing else changes.
