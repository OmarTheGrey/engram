**What.** A run journal holds `run.lock` in its output folder, naming its process id and host, from open to close; a second journal on the folder is refused (`JournalLocked`).

**Why.** The RV1 backlog row "Concurrent writers" (`docs/log/2026-11-19-rv1-finding-concurrent-writers.md`): two processes on one `--out` interleave their rows, and sharding makes several processes the normal case.

**Result.** The lock is created with an exclusive open. A lock whose holder, on this host, no longer runs (signal 0) is taken over; another host's lock, or one naming no process, is refused with the path to remove. The journal releases the lock when it closes, after a crash inside the run too. A merge refuses a shard folder whose lock is held. Tested in `rv6.test.ts` ("one process at a time writes a folder").

**Consequence.** The backlog row is closed by this card.
