**What.** Card E2.2 added the read path: candidates from the item projection, narrowed by the adapter's search when the query has text (term matching in the plane otherwise), filtered by `evaluateRead` (active only, scope membership and read matrix or a live matching grant, validity window at the query time), ranked by relevance, confidence and recency.

**Why.** Invariant 1 and ADR 0009 need a filter the plane owns and an explanation for every returned item.

**Result.** Each read appends one event whose reason states the filtered count; explanations carry rank, components, the admitting rule and grants used, and are stored under the read event id (migration 3) for `explain`. A cross-scope read returns nothing from the other team and reports one filtered item on all four registered stores.

**Consequence.** Candidate and retired items are never read and are not counted as filtered.
