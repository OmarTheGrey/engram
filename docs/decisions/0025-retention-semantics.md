# ADR 0025: Retention semantics: expiry at read and by sweep, budgets enforced in the write queue, eviction order, retired content stays out

Status: accepted, 2026-11-02
Deciders: Omar (lead)
Supersedes: nothing; it gives ADR 0010 (retention never deletes) its mechanism.

## Context

ADR 0010 says retention retires and never deletes, because eviction is what makes budgeted memories lose at nine weeks (Ground Truth First, 2607.21962) and in-place repair damages benign memory (MemSecBench, 2607.27080). The policy already carries `retention` rules per scope and class (`ttl`, `budget`, `eviction` in recency, utility or manual) and the event log has both `retire` and `evict` ops, but nothing decides when a rule fires, who runs it, how `utility` is measured, or what `manual` does. Retrieval admissibility (2610.07309) names lifecycle as one of three axes a read must check, so an item past its ttl must be inadmissible even before a sweep retires it. Bemula (2610.18052) shows every memory system fails forget requests, partly through relearning: a similar later fact re-establishes what was removed; a retired item that stays as evidence is the one advantage of retire-over-delete, and it has to be used.

## Decision

1. **A pure evaluator.** `evaluateRetention(policy, scope, items, at, usage)` in `packages/core/src/policy/retention.ts` returns the retirements a sweep would make, each with a reason and the policy id `<policy>/retention/<level>/<class>`. No clock, randomness or store I/O. Timestamps compare through the full-precision helper (decision D7).
2. **Expiry.** An item whose `valid_from` plus `ttl` is not after `at` is expired. A read excludes it as a lifecycle exclusion (counted in `filtered`, reason `engram/read/ttl`), so a sweep that has not run yet cannot leak it; the sweep then retires it with op `retire`. Expiry never touches `valid_to`: ttl is retention, validity is truth (ADR 0005).
3. **Budgets.** A rule's `budget` bounds the active items of that class in that scope. The write path runs the budget check for the written scope and class after a landing write, in the same queue slot, so after any write sequence no scope holds more active items of a class than its budget. Overage is retired with op `evict`, in the rule's order: `recency` retires the oldest by the seq of their last changing event; `utility` retires the least read, measured as the count of explanation rows naming the item (migration 3: every item a read returned), ties broken by recency; `manual` evicts nothing and appends one `evict` event with decision `ask`, `item_id` null, naming the overage, so a human sees it in the session and the inspector and every decision stays an event (AGENTS.md rule 3).
4. **The sweep.** `Plane.retain(actor, scope, at)` runs both checks over one scope and returns a `RetentionReport`. The actor must be a member of the scope (`engram/retention/membership`). It runs inside the write queue so it never interleaves with a write. The pi extension calls it after an allowed write to that scope and at `before_agent_start` for the session's scopes; `engram read` calls it before adoption. Nothing runs on a timer: the plane has no clock.
5. **Retired content stays out.** A write whose actor source is `model`, `compaction` or `tool` is denied (`engram/write/retired-content`) when an item retired in the same scope has the same normalised content hash (ADR 0018's exact rule). A `user`, `document` or `import` source may re-admit it: a person restating a fact is a new user event, which is what Bemula's relearning suite requires. The near-duplicate form of this rule waits for the duplicate lint (L1, ADR 0018).
6. **Reinstatement** is an allowed `update` event that sets `status` back to active on the retired version (ADR 0010); no new Plane method in E2.4, and a follow-up card names the surface for it.

Amendments made when implementing card E2.4, 2026-10-29 (choices this ADR left open):

- Which ttl: the tighter of the item's own `ttl` and its retention rule's (scope level and class). The event names the rule (`<policy>/retention/<level>/<class>`) when the rule's ttl decides and `engram/retention/item-ttl` when the item's own is tighter. The expiry instant is `valid_from` plus whole seconds with the fraction kept (`addSeconds` in packages/core/src/time.ts); a sum past the last four-digit-year second never expires.
- A sweep retires expired candidates as well as expired active items, so an expired candidate cannot be promoted later; retired items are left alone.
- The write path's check is the budget only, as decision 3 says: an expired item that no sweep has retired still counts toward the budget and can be evicted (op `evict`) by it. Reads exclude it either way. Running expiry in the write path too would retire items at write time and hide the read-time exclusion behind it.
- Utility counts every explanation row naming the item, from any reader and any time; ties fall to recency, then to the item id. Recency ties (none in practice, since each changing event has its own seq) fall to the id; an item with no recorded change counts as oldest.
- A manual rule asks once per write that leaves its class over budget and once per sweep that finds it over; the ask repeats until a person acts, which keeps it visible in every session that meets it.
- A refused sweep (the actor is not a member) is one event with op `retire`, decision deny, no item, `engram/retention/membership`; the enum has no other op for it and no schema change was made.
- The retired-content rule compares against every retired item in the scope, however it was retired (retention, adoption's retraction, a future owner retirement), through one normalised content hash (packages/core/src/content-hash.ts, ADR 0018's amendment). A user re-admitting the content does not lift it for later model writes while the retired copy exists; the reason names the retired item only to a writer whose read matrix lets it read the scope.
- Plane.retain and the budget check never write or delete in the store; the store keeps the item as it was written (ADR 0010's amendment).

Amendments made in the review fix pass, 2026-10-29 (PR 4, findings P4-1 to P4-12; they replace the implementation amendments above where they differ):

- Finding P4-1: the write path's budget check never evicts the item the write just landed (`enforceBudget(..., protect)`); it counts toward the budget and the victims come from the other items. Under `utility` a new item has no reads, so the literal rule would evict every new write once a scope is full of read items, which is the "deny a write over budget" this ADR rejects. `WriteResult.item` is the item as it stands after the slot, and the pi tool's text and `details.status` report the status after its sweep.
- Finding P4-2 (replaces the third implementation amendment): an item past its ttl holds no budget slot, in the write path and in a sweep. The write path still does not retire it, so the read-time exclusion stays visible; the budget is counted over active items not past their ttl, and that is what invariant 5 bounds.
- Finding P4-3 (narrows the seventh): only an item whose last allowed changing event is a `retire` or `evict` counts for the retired-content rule. An item written with status `retired` was retired by nobody (ADR 0010: items are retired by event), and counting it would let any member plant a block on chosen content in a shared scope.
- Finding P4-4: when the actor cannot read the scope (its membership and the read matrix, as finding N3 rules for write denials), a retention event's reason names no item id, seq, read count or item count: "scope <s> is over its <class> budget; an item was evicted by <order>". The event's `item_id` still names the item, since replay needs it; the pi extension mirrors events as custom entries, which are not sent to the model. The retired-content denial remains an oracle for such a writer (whether a guessed content was retired in the scope), a residual risk the next review weighs.
- Finding P4-5: the utility signal is not in the event log. Utility counts explanation rows (migration 3), which `rebuild()` leaves alone and read events do not carry, so replaying the log reproduces a utility eviction as an event but cannot re-decide it: not in a database rebuilt from the log (a backend migration, card E1.1), not from a pi session's workload, not in the simulator (card E8.9) under a candidate policy. Recency evictions can be re-decided. The fix needs a schema change and is listed under "not now" in the plan: record the returned item ids on read events.
- Finding P4-6, chosen design (option a): ttl retirement depends on the caller's clock and has no reinstatement surface yet, so a sweep retires by ttl only in the actor's own person scope (`scope` equals the actor's id), or anywhere for a `user`-sourced actor, a person's explicit act (`mayRetireByTtl`, packages/core/src/policy/retention.ts). Other sweeps run the budgets only; reads exclude expired items whoever sweeps, so nothing leaks. The pi extension sweeps as the session's actor, which carries no `user` source, so a member whose machine clock runs a year ahead retires nothing by ttl in a shared scope; `engram read` sweeps only the folder owner's own person scope. Option (b), refusing an `at` earlier than the log's latest event, does not stop a clock that runs ahead, and the first such sweep would then refuse every honest clock after it; option (c), a reinstatement event, makes the damage reversible but leaves shared memory retired until someone notices. Not taken: no surface yet lets a person run a user-sourced sweep of a shared scope, so expired shared items stay active (and unreadable) until one exists; an `engram retain` command is the follow-up. An actor's own person scope still follows its own clock, skewed or not.
- Finding P4-7: the content hash strips format characters (category Cf, such as U+200B and U+00AD) and U+180E before comparing (ADR 0018's amendment).
- Finding P4-12 (replaces the fifth implementation amendment): a manual rule's ask is appended only when no ask for that scope and rule has been recorded since the last change to any item of that class in the scope. A write is such a change, so a write that leaves the class over budget always asks; repeated sweeps of an unchanged overage do not.
- From the review's outside notes: adoption's retractions (`engram/adopt/retract`) are appended inside the write queue, and the queue refuses a call made from inside itself on the same db (`NestedWriteQueueError`, finding P4-8; ADR 0007's amendment).

Amendments made after the verification of the review fix pass, 2026-10-29 (PR 4, findings P4-13 to P4-17 and the orchestrator's decisions):

- Finding P4-13 (the orchestrator's decision): a retirement whose event names `engram/retention/item-ttl` does not make content retired, because the item's own ttl is set by its writer: a member could write content with `ttl: 1` and let the next sweep turn it into a block on everyone's model, compaction and tool writes. Expiry by a rule's ttl, budget eviction, adoption's retraction and any other allowed retire or evict still count, including those a user-sourced sweep makes under a rule. The check is one condition in `retiredContent` (packages/core/src/plane/write.ts).
- Residual risk, recorded for the lead: a member can still plant a block by budget flooding, writing the target content and then enough items for recency (or utility) to evict it, after which the eviction counts as retired content. It needs write access to the scope and leaves a trail of writes and an evict event naming the item; closing it would mean judging who caused an eviction, which this ADR does not attempt.
- Finding P4-4, the orchestrator's decision: the residuals stay as the review fix pass recorded them, for the lead to review. A redacted evict event keeps its `item_id`, since the log, the pi session's mirror of it and replay must hold the same event, and a Plane or MCP caller that is not pi receives it in `WriteResult.retention`; the retired-content denial remains a signal of whether a guessed content was retired in a scope the writer cannot read. No code change.
- Finding P4-14: the content hash strips every default-ignorable code point (with the Hangul fillers U+3164 and U+115F named as well), then applies NFKC again, so a combining mark left next to its base by a stripped character composes (ADR 0018's amendment).
- Finding P4-15: an actor's own scope for ttl retirement is a `person:` scope equal to its id; an actor whose id is `team:platform` or `org` has no own scope there and needs a user source. The verification's caveat stands, for the lead: `source: user` is asserted by the harness, not authenticated, so this rule stops the agent and unsourced sessions, not a surface that wrongly sets `user`. Until a user-sourced sweep of a shared scope exists, expired shared items are unreadable and hold no slot but are not retired, so card E2.4's "expiry retires" holds in person scopes only.
- Finding P4-1, the verification's note: the protection lasts one write. In a full utility scope whose old items are all read, each new write evicts the previous new one, so new material has one rotating slot; that is what fewest-reads means, and the lead should weigh it against the tenure crossover.
- Finding P4-16: the write queue refuses only real nesting: a call made from a slot's async context while that slot still runs. A timer or listener created in a slot that fires after it ended queues normally (ADR 0007's amendment).
- Finding P4-17: the pi extension's report of an item its post-write sweep retired is now tested.

Amendment made by the schema version 1 PR, 2026-11-06 (branch `schema-v1`):

- Finding P4-5 is closed: utility counts the read events that returned an item, by their `item_ids` (schema version 1), not the explanation rows, so a database rebuilt from the log or a log replayed elsewhere decides a utility eviction again (`packages/core/test/unit/plane/retention.test.ts`, "utility replays from the log alone"). Migration 4 filled in the ids of every older read from its explanation rows. A utility eviction's reason says how many reads returned the victim ("N reads returned it"). Counting reads is a scan of the read events, once per write that meets a utility budget; an index or a counter is left until a workload needs it.

## Alternatives considered

- Deny a write that would exceed the budget instead of evicting: contradicts ADR 0010's reading of the tenure crossover (the new material is what the agent needs now) and the preset comments; not taken.
- Utility as an LLM-rated importance score (Generative Agents, 2304.03442): a model call on the plane's write path, against AGENTS.md rule 4; reads-returned is the deterministic proxy MERIT's marginal-utility framing supports (2609.05441).
- A background timer for expiry: core reads no clock; surfaces inject `at`.
- Deleting on budget overage: ADR 0010.

## Consequences

Card E2.4's acceptance ("budget exceeded evicts per policy; events recorded") has a definition. The lead-owned invariants gain a fifth property (budget never exceeded after any write sequence; every retire or evict carries a reason and a policy id; replay reproduces them) and invariant 1's oracle excludes expired items; a second reviewer and a `decision` entry go with that change. The preset ttl and budget numbers stay proposed values. Changing this decision needs a new ADR that supersedes this one and a `decision` log entry.
