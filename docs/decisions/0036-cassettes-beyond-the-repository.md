# ADR 0036: Cassettes beyond the repository: live cassettes are deposited on Zenodo and fetched by sha256, and external harnesses replay through a local cassette proxy

Status: accepted, 2026-11-20, under the lead's delegation (`docs/tasks/lead-decisions.md`, items 27 and 29); the lead may overturn it
Deciders: the orchestrating session, under the lead's delegation of 2026-11-20
Supersedes: nothing. It extends ADR 0017 (every model call is cached, metered and seeded; cassettes are the cache) to two cases ADR 0017 does not cover.

## Context

- **Where the cassettes go.** Rules 7 and 9 make a result real only if it regenerates from its cassettes. The cassettes of H1's live runs are about 0.9 to 2 GB (RV-DES-14). That is too large for the repository and lost if kept only on one member's disk. The lead already chose a Zenodo deposit for the pre-registration's mirror (decision-sheet item 3a; ADR 0023).
- **External harnesses.** MERIT, MemoryAgentBench and tau2 run their models through LiteLLM, outside `@engram/model`'s cached and seeded call (RV-DES-6). Their calls are neither cached under rule 7 nor seeded under rule 6.
- **The cost of porting.** Porting each harness to TypeScript takes weeks per harness.

## Decision

1. **The deposit.** Every live run's cassette folder is deposited on Zenodo when its results are committed, one record per run. A fetch script under `research/scripts/` downloads a deposit into the path the run's config names, and checks each file against a committed sha256 list before any replay reads it. A file that is missing or does not match is an error.
2. **The proxy.** External harnesses reach models only through a local proxy in `@engram/model`. It listens on loopback, speaks the OpenAI chat-completions API, and serves every request through the same cached and seeded call as the runner. The cache key is the same as ADR 0017's, with the harness, item, condition and seed passed by the harness's config.
3. **Proxy modes.** The proxy has the runner's modes: replay, with a miss as an error, by default; record, only under the live flags and refused under `ENGRAM_OFFLINE=1`.
4. **The harness configuration.** A harness configured with any other endpoint is refused by its research config. This is a configuration check, not a network control, and that limit is stated.

## Alternatives considered

- **Keep cassettes locally only** (item 27, option b). The results could then not be regenerated by anyone else, which breaks rule 9 for the thesis's examiners.
- **Commit the cassettes with Git LFS.** That adds a dependency and a storage cost for files the repository never diffs.
- **Port each harness to TypeScript** (item 29, option b). That takes weeks per harness and risks diverging from the upstream judges this project vendors (ADR 0015).
- **Accept unseeded harness calls as a stated exception.** That gives up rules 6 and 7 for three of the six benchmarks.

## Consequences

- Cards follow: the fetch script, the deposit procedure in `docs/conventions/`, and the proxy in `@engram/model` with conformance tests against the runner's cache.
- The proxy needs no new dependency beyond Node's `http` module. Any dependency that is needed goes in `docs/deps.md`.
- A Zenodo deposit is public and permanent. Cassettes hold only benchmark content and model replies, never dogfood content (rule 12).
- The thesis cites each deposit's DOI beside its results.
