# ADR 0002: Memory item schema, versioning and generated contracts

Status: accepted with amendments, pending lead review, 2026-10-22
Deciders: drafted by the coding agent in step-0 task S0.13; pending review and acceptance by Omar (lead). Until then this records a recommendation the code already follows.
Supersedes: the proposal of the same number in `docs/decisions/README.md`

## Context

CoALA's three classes (episodic, semantic, procedural); Zep's bi-temporal edges; Eywa's evidence-before-belief; MemOS's MemCube, which we must compare to field by field; the roadmap rule that schema changes are one PR.

## Decision

(a). Zod 4 has native JSON Schema export with `io`, metadata and registries, and the extension already lives in TypeScript. Fields: `id` (UUIDv7), `class`, `scope`, `owner`, `content`, `provenance`, `confidence`, `valid_from`, `valid_to`, `ttl`, `grants`, `version`, `lineage`, `status`, `store_ref`, `schema_version`. Every field has a one-line meaning in `docs/glossary.md`. `make api` fails CI on a dirty diff.

Amendments made when deciding:

- Implemented in step-0 task S0.7 (`packages/core/src/schema.ts`) following `docs/architecture.md`: scope is the string `person:<id>`, `role:<id>`, `team:<id>` or `org`; `ttl` is in seconds; `store_ref` is `{adapter, key}` or null; a grant is `{to, class?, mode, expires?}`.
- MemoryItem is a union on `class`: procedural content is `{body, tools}`, other classes carry text or a structured payload. A fixture showed a procedure without a tool list passing as a generic payload.
- A MemoryEvent carries the `item` it produces, for replay, and optional `usage`. `schema_version` starts at 0.
- Python types are TypedDicts generated by datamodel-code-generator; `make api-check` fails on a dirty tree.

## Alternatives considered

(a) Zod 4 as the single source, JSON Schema via `z.toJSONSchema`, Python types generated from the JSON Schema. (b) JSON Schema hand-written, codegen both ways. (c) TypeBox.

## Consequences

Unblocks E0.2, every adapter, the Python analysis types. Changing this decision needs a new ADR that supersedes this one and a `decision` log entry.
