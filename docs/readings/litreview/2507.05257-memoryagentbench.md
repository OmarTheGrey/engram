## Claim
Memory agents need four competencies (accurate retrieval, test-time learning, long-range understanding, selective forgetting), and when long-context datasets are fed incrementally as multi-turn chunks, no method from RAG to Mem0, Zep and MemGPT masters all four; selective forgetting is the weakest.

## Method
Each source text is split into chunks (512 tokens for single-hop, multi-hop, LongMemEval and forgetting tasks; 4096 otherwise), each wrapped in a user message with a memorise instruction and sent in order, then questions follow (Sec. 3.3, 4.1). Datasets (Table 2): retrieval from document QA, a LongMemEval subset and the new EventQA; test-time learning from five classification sets and movie recommendation; long-range understanding from InfiniteBench summarisation and Detective QA; selective forgetting from the new FactConsolidation sets built from MQuAKE edit pairs. Agents: six long-context models, BM25 and four embedding RAGs, structure-augmented systems (RAPTOR, GraphRAG, MemoRAG, HippoRAG-v2, Mem0, Cognee, Zep), and agentic memory (Self-RAG, MemGPT, MIRIX) (Sec. 3.2).

## Key numbers
- 2,071 questions; context depth 103K to 1.44M tokens (Table 1).
- Best overall: GPT-5-mini long-context, AR 74.4, TTL 48.6, LRU 66.2, SF 53.0, overall 60.6 (Table 3).
- BM25: AR 60.5, overall 41.5; HippoRAG-v2 AR 65.1, best among RAGs (Table 3).
- Mem0: AR 32.6, LRU 20.7, overall 21.1; MemGPT 28.3; MIRIX (4.1-mini) AR 63.0, overall 37.7 (Table 3).
- Multi-hop forgetting: no method above 28 percent (Sec. 4.2); o4-mini on FC-MH 80.0 at 6K context, 14.0 at 32K (Table 5).
- Default top-k 10, about 40K tokens at 4096 chunk size (Sec. 4.3.2).

## What Engram borrows
FactConsolidation is the closest public test of ADR 0005: a later chunk edits a fact and the agent must answer with the new value. Engram runs it under every condition because an enforced supersede rule should raise it while an ungoverned Mem0 path (already low here) should not. The chunked ordered ingestion is exactly what the pi runner does: each chunk passes through the write gate (ADR 0007), so the benchmark doubles as a throughput test for the governance tax (H2). The repository's metric table, `substring_exact_match` for most tasks and GPT-4o only for LongMemEval and summarisation, lets Engram report H1 on deterministic and judge-based strata separately (ADR 0015).

## What Engram does differently
MemoryAgentBench scores the memory agent as a whole. Engram does not try to fix Mem0 or Zep; it asks whether a policy layer above an unchanged store changes the outcome and reports the store's native score as the ungoverned baseline. Engram adds a cost axis the paper omits.

## Risk to our claims
Long-context GPT-5-mini beats every memory system on three of four competencies. If the long-context condition wins here at every budget, H2 has no knee on this benchmark and H4 rests on the other five. Mitigation: pre-register that MemoryAgentBench feeds H1 and H5 only through the forgetting and retrieval strata, and report the long-context ceiling honestly.

## Open question
The README says `exact_match` parsing is strict ("label: 43" fails against "43"). Does injecting explanations into context change answer formatting enough to lose points, and should Engram normalise before scoring?

## Notes
Dataset: 2,071 questions over 13 tasks; auto-downloads from Hugging Face (ai-hyz/MemoryAgentBench). Task types: QA, classification, recommendation, summarisation, fact consolidation. Judge: deterministic (substring or exact match, Recall@5, F1) for most tasks; model-based (gpt-4o) for LongMemEval and summarisation. Plug-in: `--agent_config` and `--dataset_config`; `agent.py` and `methods/` exist but no base class is documented, so an external agent needs a new method file inside the repo. Licence: code MIT, datasets CC BY 4.0, third-party sources keep their terms. Version read: v4, June 2026; ICLR 2026 acceptance in the README. Limitations: only representative agents due to budget (Conclusion); RAG and commercial agents weak on test-time learning and long-range understanding (Sec. 4.2). The README calls the fourth competency "Conflict Resolution"; same datasets. HippoRAG needs its own environment because of an `openai==1.58.1` pin.
