## Claim
A memory can be retrieved correctly and still used wrongly when its lifecycle or validity state is corrupted, and restoring the control state with an oracle restores the context, so control-state integrity should be evaluated beside retrieval accuracy.

## Method
Fault operators (deletion, temporal supersession, missing metadata and related) corrupt the governance state while stored content and task stay fixed. 731 benchmark-grounded bases (380 deletion, 169 temporal, from Memora, LongMemEval and OAKS Novel) give 2,080 matched fault pairs across six providers. Three conditions per pair: clean, corrupted, and enforced (oracle-backed restoration before context construction). Offline control-plane checks measure change in the operative projection; downstream tests use LongMemEval and Memora.

## Key numbers
- Corruption changes the operative context in 96.25 percent of pairs; oracle enforcement restores 100 percent (abstract).
- Downstream contrasts: 40.54 points on LongMemEval binary correctness (95 percent interval 30.32 to 50.71) and 30.60 points on rescaled Memora FAMA (23.31 to 37.69) (abstract).
- OAKS Novel option parity holds for 6,714 resolved outputs. Full-panel effects of minus 27.55 and plus 27.51 are described by the authors as descriptive proxies.

## What Engram borrows
The matched clean, corrupted, enforced triple is a ready design for a fault-injection arm of H3: seed a supersession or deletion fault in the log, then show that replay restores the operative context. The "did the admitted set change" projection check is a cheap deterministic metric for the invariants file.

## What Engram does differently
Their enforcement is an oracle upper bound, not an implemented gate. Engram's log supplies the state the oracle assumes, so the oracle is something we can build.

## Risk to our claims
The authors state that oracle recovery is not autonomous recovery. If our lints cannot rebuild state from events, H3's recovery claim is bounded by the same gap.

## Open question
What fraction of their fault pairs would Engram's deterministic lints detect without the oracle?
