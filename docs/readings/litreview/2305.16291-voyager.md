## Claim
An LLM agent that writes executable skills, verifies each one with a separate critic before storing it, and retrieves stored skills by description can keep learning in an open world without fine-tuning, and the stored library transfers to a new world.

## Method
Three parts (Sec. 2, Figure 2): an automatic curriculum where GPT-4 proposes the next task from the agent's state and the goal of discovering diverse things (Sec. 2.1); a skill library that stores each skill as a program in a vector database, keyed by a GPT-3.5 embedding of the program's description, retrieved top-5 per task (Sec. 2.2, Figure 4); and iterative prompting with environment feedback, execution errors and self-verification, up to four rounds per task before moving on (Sec. 2.3, Alg. A.1). A skill is added only after a separate GPT-4 critic confirms the task was completed; on failure the critic writes a critique that feeds the next round (Figure 6). Models: gpt-4-0314 for code and curriculum, gpt-3.5-turbo-0301 for auxiliary steps, text-embedding-ada-002, temperature 0 except 0.1 for the curriculum (Sec. 3.1). Baselines ReAct, Reflexion, AutoGPT in Minecraft (Sec. 3.2).

## Key numbers
- 63 unique items within 160 prompting iterations, 3.3 times the baselines (Sec. 3.3, Figure 1).
- Tech tree milestones reached 15.3 times faster for wooden tools, 8.5 for stone, 6.4 for iron; only Voyager reaches diamond, in 1 of 3 runs; ReAct and Reflexion unlock no tier (Table 1).
- 2.3 times the traversed distance (Sec. 3.3, Figure 7).
- Ablations: random curriculum cuts discovered items by 93 percent; removing self-verification cuts them by 73 percent; GPT-3.5 in place of GPT-4 yields 5.7 times fewer items; without the library progress plateaus (Sec. 3.4, Figure 9).
- New world, empty inventory: all four unseen tasks solved within 50 iterations; baselines solve none except AutoGPT given the library (Table 2, Figure 8).
- GPT-4 costs about 15 times GPT-3.5 (Sec. 4).

## What Engram borrows
Store only after a verified run: a candidate needs at least one judged success before it can enter replay (ADR 0011, D3). The critic is a model separate from the actor; the replay judge is injected as a ModelCall, never the acting model's own claim (rule 4, D3). Retrieval by a description field with a bounded top-k becomes the procedure retrieval default, with the explanation carrying rank and score (ADR 0009). Skills calling earlier skills motivates a lineage field on procedures (ADR 0002).

## What Engram does differently
Voyager has no lifecycle: one critic pass admits a skill and nothing ever leaves the library. Engram admits after k of n replay on held-out tasks, tracks a smoothed success rate, and retires on drift or environment change. Voyager's skills are code against a fixed game API; Engram v1 procedures are text over tools that change between sessions, so verification cannot rely on a deterministic simulator.

## Risk to our claims
Self-verification is the single largest lever after the curriculum (73 percent of items lost without it, Figure 9), and one critic pass captures it. If a single verified success already yields most of the durability, k of n replay adds cost without measurable gain, and H5's cost side worsens. Mitigation: if budget allows, run critic-only admission as a sub-condition of H5; otherwise report the replay cost per admitted procedure so the trade is visible.

## Open question
The critic misses real successes, such as spider string (Sec. 4). What is the false-negative rate of a replay judge on pi coding tasks, and at what rate does it starve the candidate pool? Measure on the step-0 session fixture before fixing k and n.
