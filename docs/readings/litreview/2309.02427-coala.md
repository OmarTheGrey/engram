## Claim
Language agents can be described with one vocabulary borrowed from classic cognitive architectures: four memory types, an action space split into internal (retrieval, reasoning, learning) and external (grounding) actions, and a decision cycle. Writing to procedural memory is the riskiest form of learning and should be restricted by design.

## Method
A conceptual framework, not an experiment. Section 2 traces production systems and Soar; Section 4 defines working, episodic, semantic and procedural memory (4.1), grounding (4.2), retrieval (4.3), reasoning (4.4), learning (4.5) and decision making (4.6, with a planning stage of proposal, evaluation, selection and then execution). Section 5, Table 2, classifies five agents (SayCan, ReAct, Voyager, Generative Agents, Tree of Thoughts) by long-term memory, grounding, internal actions and decision procedure. Section 6 gives design recommendations; Section 7 lists open questions. No datasets, models or baselines.

## Key numbers
- none stated in the sources read. Table 2 (Section 5) lists five agents; only Voyager has writable procedural memory, only Generative Agents has writable episodic and semantic memory.

## What Engram borrows
- The three long-term classes become the `class` field (episodic, semantic, procedural), ADR 0002. CoALA's working memory is the pi context, not a stored class.
- The warning in Section 4.1 that writing to procedural memory "is significantly riskier than writing to episodic or semantic memory" is the stated motivation for the procedural lifecycle in ADR 0011: candidate, replay admission, retire on drift. This is the basis of H5's "governed" qualifier.
- Section 6's retail example, where an agent has read-only access to semantic and procedural memory, is the first published statement of per-class write permissions. It maps to write rules keyed on (scope, class, source kind) in ADR 0006 and 0007.
- Section 6's suggestion to "specify and ablate the agent's action space for worst-case scenario prediction" is what the policy simulator does over a session JSONL with a candidate policy (ADR 0001 mapping row for the simulator).
- The decision cycle terms (proposal, evaluation, selection) name the stages of the distiller in D2: mined candidates are proposed, replay-validated, then selected for activation.

## What Engram does differently
CoALA is descriptive; it names the risk of self-modifying procedures and recommends restricting the action space but gives no mechanism. Engram puts the restriction in a gate the agent cannot bypass, records every decision as an event with a reason, and measures whether enforcement beats instruction (H1). CoALA also treats memory as something the agent owns; Engram adds scope, owner and grants so one store serves several principals.

## Risk to our claims
CoALA says the designer must bootstrap procedural memory and that no agent it knows learns new learning or decision procedures (Section 4.5). If governed procedural memory only ever yields "new code skills" of the Voyager kind, H5's net positive may be small and confined to tool-use tasks. We would pre-register H5 on tasks where Agent Workflow Memory already reports gains and state that generalisation beyond them is not claimed.

## Open question
CoALA puts retrieval inside the decision cycle, so an agent chooses what to recall. Engram's read filter runs before the model sees anything. Do we ever want the agent to request a recall that policy then explains and denies, and should that denial be visible to it?
