## Claim
Persistent memory makes users disclose more over sessions, because the agent carries earlier attribute values forward as presuppositions and users affirm or fail to correct them, so guesses become recorded facts.

## Method
Simulated users with 24 personal attributes talk to support agents with and without memory across sessions, on four support models. Leakage of personal attributes and response quality are tracked per session. Interventions: instructing the agent not to state or presuppose attributes, and filtering or anonymising user inputs or stored data.

## Key numbers
- Memory raised response quality and attribute leakage, and the gap grew over sessions (abstract).
- Removing the agent's mentions of an attribute reduced later disclosure about twice as much as single-turn effects predicted (abstract).
- Instructing the agent not to state or presuppose attributes brings leakage near the no-memory level and keeps most of the quality gain; filtering or anonymising inputs or stores preserves less of the benefit (abstract).

## What Engram borrows
A Twin lint idea: an inferred or agent-asserted attribute should enter person scope as a candidate with source model, not as a user fact, until the user confirms it. That is the plane's provenance rule applied to inference, and the loop gives a concrete scenario for a Twin acceptance test.

## What Engram does differently
Their effective mitigation is an instruction to the agent. Engram would enforce at the write gate (source model cannot write a user-attribute item as user-sourced) and at read (do not surface unconfirmed attributes as presuppositions), consistent with H1's enforcement over instruction.

## Risk to our claims
Their finding that an instruction works nearly as well as no memory is a point for instruction conditions in H1 for this class of harm. Action: run H1's instruction arm for the Twin scenario honestly and report where it holds.

## Open question
Does a confirmation step on inferred attributes cost more utility than the instruction?
