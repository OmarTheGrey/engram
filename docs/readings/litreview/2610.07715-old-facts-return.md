## Claim
Identity-keyed temporal memory is accurate until a retired value is re-read verbatim, when it is revived. A guard that refuses to reactivate a retired value fixes that, but cannot tell a legitimate revert without change provenance.

## Method
130 extractor-selected atomic transitions from software fixes, under ordinary and re-read conditions, with a model judge and a literal stale-value proxy. Abstract only.

## Key numbers
- Ordinary: 98.5% accuracy, no observed stale errors (abstract).
- Re-read of the old statement: accuracy 10.8%, stale-value rate 88.5% (abstract).
- With the guard: 97.7% accuracy, stale rate 0.8% (abstract).

## What Engram borrows
A ranking must never revive a retired item. The retired-content gate (ADR 0025) does this at write; the hybrid tier must rank only active, admitted items. A property test in AB-RET-1.

## What Engram does differently
Engram keeps bi-temporal validity and retire events, so a revert is a recorded write with provenance rather than a guess.

## Risk to our claims
Our recency component rewards newer items, which a re-read could exploit if retirement is not honoured before ranking.

## Open question
Should recency decay count valid_from or last confirmation?
