## Claim
A multi-tenant memory service that implements scoped retrieval, temporal supersession, provenance and policy-governed propagation as service primitives can be probed live, and live probing finds enforcement bugs that design review does not: a sub-tenant scope bypass on get-by-id and a dedup gate that swallows contradictions before the detector sees them. The paper is a systems report on one production service, with no comparand.

## Method
MemClaw is a hosted memory API with four scopes, Agent-local, Team-shared, Tenant-global and Restricted, nested agent in fleet in tenant (Table 1, Sec. 3.2). Credentials are tenant- or agent-scoped `mc_` keys; the gateway injects X-Agent-ID and strips any client-supplied value (Sec. 6.1). Items carry creation time, optional `supersedes_id`, contradiction markers, provenance (writer identity, source system, derivation via `metadata.derived_from`) and confidence (Sec. 5.3, 5.4). Contradiction detection runs asynchronously after commit on (subject, predicate, object) triples for single-valued predicates (Sec. 7.2). Propagation is a trust ladder 0 to 3 (read-only, write home fleet, cross-fleet read, cross-fleet write), with `redistribute` requiring trust 3 (Sec. 7.1). ArgusFleet is a Python harness with seeded plans and JSONL traces that runs four experiments against the live REST API: leakage (4 fleets by 6 agents, 192 probes), contradiction (100 facts from 20 templates, sequential and concurrent, N=200), provenance (50 depth-4 chains, 200 writes) and propagation (40 facts, 200 probes) (Sec. 6.2, 7). No LLM is in the loop; the evaluation targets the service.

## Key numbers
- Provenance chain completeness at depth 4: 1.000, Wilson 95 percent CI [0.929, 1.000], 50 chains; writer identity accuracy 1.000; per-hop fetch latency 291 / 491 / 1,076 ms at p50 / p95 / p99 (Table 2, Sec. 8).
- Fleet-sibling visibility 0.975 (n=120); cross-fleet leak rate 0.000 (n=80, CI [0, 0.046]); visible-window p50 / p95 0.83 / 1.63 s (Table 2, Sec. 8.3).
- Semantic search leak rate under tenant authority 0.439 (n=164, CI [0.365, 0.516]); semantic search miss rate 0.143 (n=28); in-scope GET miss 0 of 28 (Table 2, Sec. 8.1).
- Before remediation a trust-1 agent could GET a cross-fleet row by id; after the 2026-05-31 fix, 0 of 36 cross-fleet (Sec. 8.1, 9.1).
- Contradiction detection across all runs 0.490 (n=200); when both writes were admitted 1.000 (n=90); only 194 of 400 planned contradiction writes succeeded because the near-duplicate gate rejected the rest (Table 2, Sec. 8.4, 9.2).
- Write latency p50 / p95 / p99: 1,840 / 4,861 / 19,319 ms (Table 2).

## What Engram borrows
Two production findings become test fixtures. The get-by-id bypass is exactly invariant 1 evaluated on the wrong path: ADR 0006's read matrix must apply to every read entry point, including fetch-by-id, and S0.9's property test should generate direct-id reads, not only searches. The dedup-starves-contradiction ordering bug is a sequencing rule for ADR 0008 and ADR 0018: the duplicate lint must run after, or in the same transaction as, the contradiction lint, and a rejected near-duplicate must still emit an event carrying the candidate so the contradiction lint can see it. The trust ladder maps onto grants (ADR 0006) and the `redistribute` call onto the promotion gate between scopes. ArgusFleet's seeded-plan plus JSONL-trace design is the shape of Engram's conformance suite for real stores (ADR 0013, A1 to A3).

## What Engram does differently
MemClaw is a store with governance inside it; Engram is a plane above stores it does not own (Mem0, Letta, files), so the same four primitives are enforced by interception rather than by the store's API, and the H4 claim is that they hold across stores. MemClaw's contradiction detector is structural and asynchronous; Engram's is a lint that emits an event and can retire a version with lineage (ADR 0005, 0008). MemClaw has no evaluation of downstream agent utility; Engram measures the tax (H2) on benchmarks with model calls.

## Risk to our claims
Their semantic-search leak rate of 0.439 under tenant authority (Table 2) shows that scope on the row is not enough when the search index spans scopes. If Engram relies on a store's native search (ADR 0013 `native_search`), the read filter must post-filter every hit and the explanation (ADR 0009) must show the filtered-out count, or invariant 1 holds for direct reads and fails for search. The fix is cheap but must be in the conformance suite before any H1 run.

## Open question
Their p99 write latency of 19 seconds comes from synchronous dedup plus async contradiction checks. What is the latency budget for Engram's write gate on pi's `tool_call` path, and does H2's knee show up in wall clock before it shows up in tokens?
