## Claim
Evaluating memory systems per operation (extract, update, answer) rather than end to end shows errors are made at extraction and update and then carried into question answering; most systems omit more than half of required updates, and at 1M tokens Mem0's extraction recall falls to about 3 percent.

## Method
Twenty synthetic users with GPT-4o-verified personas produce HaluMem-Medium (30,073 dialogue rounds, about 160k tokens per user) and HaluMem-Long (53,516 rounds, about 1M tokens per user with distractor content); both carry 14,948 labelled memory points and 3,467 QA pairs (Sec. 4, Table 2, README). Eight annotators rated 700 sessions at 95.70 percent correctness (Sec. 4). A memory system exposes three APIs, Add Dialogue, Get Dialogue Memory and Retrieve Memory; sessions are fed in order and evaluation runs after any session carrying reference memories or questions (Sec. 5). Metrics: extraction recall, precision, false-memory resistance, F1; update accuracy, hallucination rate, omission rate; QA correctness, hallucination, omission (Sec. 5.1 to 5.3). GPT-4o scores and answers (Sec. 6.1, Appendix D.2). Systems: Mem0, Mem0-Graph, Memobase, MemOS, Supermemory, Zep.

## Key numbers
- Medium, extraction recall / update accuracy / update omission / QA correctness: Mem0 42.91 / 25.50 / 74.02 / 53.02; MemOS 74.07 / 62.11 / 37.48 / 67.23; Memobase 14.55 / 5.20 / 94.25 / 35.33; Zep n/a / 47.28 / 52.31 / 55.47 (Table 3).
- Long: Mem0 3.23 / 1.45 / 98.51 / 28.11; MemOS 81.90 / 65.25 / 34.47 / 64.44 (Table 3).
- Update hallucination rates all below 2 percent, attributed partly to few samples reaching update (Sec. 6).
- No system exceeds 70 percent QA correctness (Sec. 6).
- Human verification: 700 sessions, correctness 95.70 percent, relevance 9.58, consistency 9.45 of 10 (Sec. 4).

## What Engram borrows
HaluMem is the strongest argument for ADR 0008's rule that lints run per operation and are logged as events: an update that silently omits (74 percent of the time for Mem0) is invisible end to end and visible at the write gate. The three-API shape matches the `Adapter` contract in ADR 0013, so the conformance suite gains a HaluMem-style fixture: after each session, the items the adapter holds are diffed against labelled memory points, and omission and hallucination rates become per-store conformance numbers. Update omission becomes the H3 target for the duplicate and supersede lints.

## What Engram does differently
HaluMem attributes errors to the store's extractor and updater. Engram replaces neither; it intercepts the write, so a hallucinated extraction can be refused for missing provenance and an omitted update can be flagged as a stale duplicate, but a correct update the store never proposes cannot be recovered by governance. The thesis states that boundary.

## Risk to our claims
If Mem0 extracts 3 percent at 1M tokens, almost nothing reaches the gate on long histories, and governed and ungoverned conditions converge to near zero on exactly the long-horizon arm ADR 0010 requires. Mitigation: report per-store effects, and include the files adapter and Letta, whose write paths do not depend on an extractor that collapses.

## Open question
Zep could not be scored on extraction because its API cannot list all memories for a session. Which of Engram's adapters can satisfy `list` for a scope completely, and does the conformance suite fail one that cannot?
