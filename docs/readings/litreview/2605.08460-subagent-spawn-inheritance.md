## Claim
When one agent in a multi-agent network is compromised, state it passes to subagents it spawns, memory included, carries the compromise into the children. Inheritance is a security surface in its own right, not an implementation detail.

## Method
Read from the abstract only: the authors model subagent spawn, name four failure classes (insecure memory inheritance, weak resource control, stale post-spawn state, improper termination authority), demonstrate them in real agent frameworks and propose defences stated as explicit security invariants. The full paper was not read.

None stated in the sources read.

## What Engram borrows
A fault class and a test shape. A child agent must not read its parent's memory by inheritance: it reads through its own actor and its own memberships, so the read filter is the inheritance boundary. A property test over the ADR 0006 read matrix can draw a parent actor and a child actor whose memberships are a subset of the parent's, and assert that the child never reads an item in a scope it is not a member of unless a grant names it. "Stale post-spawn state" maps to grant expiry and offboarding (ADR 0021, card E9.7): a child spawned before a grant is removed must lose the read at its next call.

## What Engram does differently
Engram has no spawn model. It sees only the actor of each call, so inheritance is whatever the harness puts in `memberships`; the plane cannot tell a child from a fresh agent.

## Risk to our claims
If harnesses copy the parent's `memberships` to every child, the plane enforces nothing between them, and "every read is filtered" holds at the level of the person, not the agent. Mitigation: document the attenuation rule at the harness boundary and test it (AB-GAP3-2).

## Open question
Which of the paper's four classes is observable from the event log alone, with no spawn event?
