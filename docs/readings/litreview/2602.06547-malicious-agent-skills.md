## Claim
Community skill registries contain deliberately malicious skills, so importing a skill is importing instructions and code that run with the user's privileges.

## Method
The authors collected 98,380 skills from two registries and combined static pattern matching with dynamic behavioural verification to confirm which were malicious. They report two main strategies: credential theft through remote code execution, and manipulation of the agent through adversarial instructions in documentation.

## Key numbers
- 98,380 skills; 157 confirmed malicious; 632 vulnerabilities across 13 attack techniques; about 4.03 per malicious skill (abstract).
- Over half of the confirmed cases came from one actor using templated brand impersonation (abstract).
- Two related results seen only in search summaries and not verified: 26.1 percent of 31,132 skills with at least one vulnerability (arXiv 2601.10338), and a claim that scanners over-label (arXiv 2603.16572).

## What Engram borrows
Import governance. Every imported skill is a candidate whose body is untrusted data, scanned by deterministic lints (instructions to hide actions from the user, remote-code fetch, credential paths, undeclared scripts) before it can be promoted. The two attack classes become fault fixtures for H3 and an import-poisoning arm.

## What Engram does differently
Detection is a lint with a reason plus review, not a verdict. Scanners over-flag, so a finding does not decide alone.

## Risk to our claims
Scanner precision is contested (2603.16572), so any lint claim must report precision on labelled data, not recall alone.

## Open question
