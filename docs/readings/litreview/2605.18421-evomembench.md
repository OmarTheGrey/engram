## Claim
Across 15 memory methods and three long-context baselines on a grid of in-episode vs cross-episode and knowledge vs execution, long-context models stay strong, memory helps mainly when context is insufficient or tasks are hard, and no single memory form wins everywhere; procedural memory suits execution tasks when stored experience fits the task structure.

## Method
The benchmark reuses six source pipelines and only swaps the backbone or attaches a memory module (Sec. 3): in-episode knowledge from MemoryAgentBench (retrieval 2,000, forgetting 800); in-episode execution from BFCL multi-turn long-context (four subsets of 200); cross-episode knowledge from CL-Bench (884 samples, 120 contexts); cross-episode execution from BFCL multi-turn base, xbench DeepSearch plus WebWalkerQA (270), and ALFWorld (200). Memory is a state updated from observation, action and outcome; in-episode memory resets per episode, cross-episode memory persists and can be frozen for transfer (Sec. 3). All 15 methods run on DeepSeek-V3.2: BM25, Qwen3-Emb-4B, GraphRAG; MemAgent, MemoBrain; Mem0, A-MEM, MemOS, MemoryOS; AWM, SkillWeaver, AgentKB, ACE, ReasoningBank; MemEvolve. Baselines: Gemini-3-Flash, GPT-5-mini, DeepSeek-V3.2 (Sec. 4).

## Key numbers
- In-episode knowledge: Gemini-3-Flash best overall rank 1.00; BM25 leads memory methods at 4.17 (Table 3).
- In-episode execution: best memory beats DeepSeek-V3.2 (28.5 / 35.5 / 45.3 / 39.5 at 16K / 32K / 64K / 128K) by +14.5, +14.0, +7.8, +8.5; ReasoningBank best at 16K (43.0), 32K (49.5), 128K (48.0), AWM at 64K (53.1) (Table 4, Finding 3).
- Cross-episode knowledge: GPT-5-mini 60.8 Easy vs best memory 50.0; DeepSeek-V3.2 52.1 Easy, 0.0 Hard; ACE 13.0 Hard, BM25 10.1 (Finding 5).
- Cross-episode execution family ranks: retrieval best for tool use (5.43), general long-term for web search (5.38), procedural for embodied (5.60) (Sec. 5).
- Tool-use transfer is stable and positive (Figure 3); ALFWorld transfer often neutral or negative (Figure 4).

## What Engram borrows
This is the reference map for H5. Engram induces workflows with AWM (ADR 0012), and EvoMemBench reports AWM and ReasoningBank on BFCL multi-turn at four budgets, which gives H5 a published ungoverned baseline. The finding that procedural memory helps only when stored experience fits the task is why ADR 0011 admits a procedure only after replay on held-out tasks and retires it on drift: unfit procedures are the negative transfer in Figure 4. The 16K to 128K budget sweep is adopted for the H2 knee plot. The efficiency metric, tokens from agent and memory module separately, is the split ADR 0017 keeps.

## What Engram does differently
EvoMemBench compares memory methods with no admission step; every induced item is used. Engram measures what changes when procedures must pass replay before use and are retired when success decays. EvoMemBench runs one backbone; Engram runs three providers (H4).

## Risk to our claims
Long-context baselines win the knowledge quadrants outright. If the long-context condition dominates on tau2-bench and MemoryAgentBench at affordable budgets, H5's "net positive" must be shown against that baseline, not no-memory, and the thesis must say procedural memory earns its place only on execution tasks at small budgets. Mitigation: pre-register H5 on execution benchmarks with long-context as the comparator.

## Open question
At 128K, MemAgent falls below no-memory (37.0 vs 39.5). Is the harm from the memory content or the context it displaces, and can the explanation record (ADR 0009) tell them apart afterwards?

## Notes
Dataset: roughly 5,000 samples across six sources (Sec. 3). Task types: QA, rule application, tool-call sequences, web search, embodied tasks. Judge: answer accuracy for knowledge tasks, success rate for execution; LongMemEval subsets use `longmem_qa_evaluate.py` (model judge), EventQA reports recall, others substring match; the CrossEp-Know grader is undocumented (README). Plug-in: add a backend under `EvoMemBench-Memory-Systems/`, write a task adapter, register in that task's memory factory; the README suggests copying an existing `mem0` script, so code lives inside the repo.
