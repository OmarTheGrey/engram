## Claim
Any memory defence that judges content or derivation history can be laundered: the agent's own summary, a trusted tool echoing attacker text, or planted corroboration can raise the effective authority of untrusted content. Binding authority to the write-time origin channel, making it non-malleable under derivation, and allowing elevation only through two independent trusted principals or a fresh action-bound user authorization is proven necessary and sufficient in a bounded model and reaches zero attack success across eight models while keeping utility.

## Method
The paper defines three laundering channels, self-summarization (L-a), trusted-tool echo (L-b) and manufactured corroboration (L-c), and three theorems in a TLA+ model with 3 slots, at most 2 sessions and k=2: content or lineage gates are malleable (T1), write-time origin binding is necessary (T2), origin-bound authority with corroboration-gated elevation is non-malleable and satisfies the invariant (T3) (Sec. IV). TMA-NM sets `act_class` from origin at write time (user and trusted_tool give act, agent gives inform, untrusted_external gives none); derived items inherit the maximum untrust of their inputs; tool outputs are tainted at the call boundary when any bound input is untrusted; a consequential action on an untrusted-derived value needs two independent trusted principals or a single-use user authorization bound to the exact action tuple; a hash-chained verdict log provides tamper evidence but not enforcement (Sec. IV, Alg. 1). MEM-INV-Bench covers 12 domains and five consequential tool types (pay, wire, purchase, setting-change, data-send) with sleeper, control-flow and exfiltration attacks in benign, static, adaptive and whitebox variants (Sec. V). Models: gpt-5-chat, gpt-4o-mini, claude-opus-4.1, claude-sonnet-4.5, gemini-2.5-flash, llama-4-maverick, deepseek-chat, qwen3-235b. Baselines are reimplementations: trust_score / prob_detect (LLM judge), lineage (MemLineage-style), capability_ifc (CaMeL/Fides-style). Wilson CIs and 20,000-iteration permutation tests.

## Key numbers
- Unified direct ASR: none 84, trust_score 0, lineage 0, capability_ifc 84, TMA-NM 0 percent; unified laundering ASR: 68, 68, 47, 68, 0 percent (Table I).
- Cross-model pooled ASR: none 31.2, prob_detect 10.6, lineage 11.2, TMA-NM 0.0 percent; TMA-NM 0 of 4,032 trials, CI [0, 0.1] percent (Table II, Sec. VI).
- Cross-model utility: none 95.9, prob_detect 93.0, TMA-NM 95.9 percent (Table II).
- Ablation: removing origin binding gives ASR 44 / 28 / 22 percent (static / adaptive / whitebox); removing elevation gives ASR 0 but utility 77 percent; removing the verdict log changes nothing (Table IV).
- Persistence over 0 to 8 intervening sessions: TMA-NM 0 percent, undefended 51 to 61 percent (Fig. 4).
- Four reproduced published pipelines: none 38.2, prob_detect 12.0, lineage 19.6, TMA-NM 0.0 percent; Trojan Hippo lineage 78, prob_detect 44, TMA-NM 0 (Table V).
- Decision latency: TMA-NM gate about 1.3 microseconds against about 2,000 ms for an LLM judge (Sec. VI).
- Model checking: 3,270 reachable states, 120 Action Integrity configurations, 64 corroborator sets (Sec. IV).

## What Engram borrows
Three rules go straight into ADR 0004 and 0007. First, authority is a function of `provenance.kind` set by the plane at interception, never of content: this is already the ADR 0004 stance that `model` and `compaction` are lowest trust, and this paper supplies the proof that anything else is launderable. Second, derived items inherit the maximum untrust of their inputs, which means a `compaction` item whose inputs include a `tool` item from an untrusted source stays untrusted; ADR 0004 needs a `derived_from` list on provenance so the lint "source changed" can also compute "trust ceiling". Third, promotion of an untrusted item to a scope where it can drive an action requires two independent trusted sources or an explicit user grant event (ADR 0006 promotion gates, ADR 0021 consent grants). The hash-chained verdict log is ADR 0003's event log; their ablation showing it does not change ASR is the honest framing for Engram too: the log is for audit and replay, not defence. MEM-INV-Bench is a candidate replacement or supplement for MPBench in ADR 0015 if MPBench code stays unavailable (S0.6).

## What Engram does differently
TMA-NM is a monitor inside one agent's memory with a fixed origin alphabet of four; Engram's provenance kind has six values and sits above several stores, with scope and grants as a second axis the paper does not have. Engram does not attempt formal verification; the invariants are property tests (S0.9). Engram also governs reads with explanations, which this paper leaves to the action gate.

## Risk to our claims
All guarantees are conditional on assumption A1: channels are authenticated and origin labels are correct at write time. In pi, the plane labels origin from the session entry type, and a tool result that embeds user-looking text is still `tool`. If Engram's interception ever lets a model-written summary be written with `kind: user` (for example through a compaction that quotes the user), the whole provenance claim is launderable. S0.5 must include a fixture where the model attempts to write with a forged kind and the gate overrides it.

## Open question
Their elevation rule needs two independent trusted principals. In a single-user coding session there is often only one. Is a replayed test pass (ADR 0011's admission for procedures) an acceptable second principal for promoting a procedural item, and should that be stated as a rule rather than an analogy?
