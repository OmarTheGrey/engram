## Claim
An agent that turns binary or scalar feedback on a failed trial into a short written reflection, stores it in a bounded episodic buffer, and reads it on the next trial improves across trials with no weight updates.

## Method
Three models (Sec. 3): an actor that generates text and actions (CoT or ReAct variants), an evaluator that scores a trajectory (exact match for reasoning, heuristics or an LLM for decision-making and programming), and a self-reflection model that writes the lesson. Short-term memory is the trajectory; long-term memory is a buffer of reflections bounded by a sliding window of size Omega, "usually set to 1-3", with 3 used for AlfWorld and HotPotQA and 1 for programming. Algorithm 1 loops act, evaluate, reflect, append until the evaluator passes or a trial limit is reached. Models: GPT-4 for the main results, text-davinci-003 and gpt-3.5-turbo for Table 5, starchat-beta for Table 4. Benchmarks: AlfWorld (134 environments), HotPotQA (100 questions), HumanEval and MBPP in Python and Rust, a new 40-problem LeetcodeHardGym, and WebShop in App. B.1.

## Key numbers
- HumanEval Python pass@1: 91.0 against 80.1 for GPT-4; Rust 68.0 against 60.0 (Table 1).
- MBPP Python: 77.1 against 80.1, the one loss; Rust 75.4 against 70.9 (Table 1).
- LeetcodeHardGym Python: 15.0 against 7.5 (Table 1).
- AlfWorld: ReAct plus Reflexion completes 130 of 134 tasks; 22 percent absolute gain within 12 trials (Figure 3, Sec. 1).
- HotPotQA: CoT (GT) 0.68 to 0.80, ReAct 0.39 to 0.51 with GPT-4 (Table 5); self-reflection adds 8 percent absolute beyond episodic memory alone (Figure 4c).
- Ablation on the 50 hardest HumanEval Rust problems: base 0.60, no test generation 0.52, no self-reflection 0.60, full 0.68 (Table 3).
- WebShop: no significant gain over ReAct (App. B.1).

## What Engram borrows
Two things. The evaluator is a separate component from the actor, which matches rule 4 and the injected ModelCall for the replay judge (D3). Reflections written from failures are the earliest evidence that failed trajectories carry reusable signal, which is why abandoned pi branches enter induction as negative evidence (ADR 0012). The bounded window of 1 to 3 is a retention budget by another name (ADR 0010).

## What Engram does differently
Reflexion learns within one task across retries, and the buffer is wiped between tasks. Engram learns across sessions and across people, so an item outlives the task that produced it and therefore needs provenance, scope, a lifecycle and retirement. Reflexion has no admission step; a reflection is stored because it was written.

## Risk to our claims
Figure 4c attributes only 8 points of the HotPotQA gain to reflection beyond plain episodic memory, and WebShop shows no gain at all. The lesson for H5 is that the value of distilled procedural text can be small next to just keeping the raw trajectory. Mitigation: ADR 0015 already includes a long-context no-memory condition; H5 reports the governed procedure arm against both the ungoverned arm and that baseline.

## Open question
The authors say the evaluator's self-judgement has no formal guarantee (Sec. 1). On coding tasks with tests, the evaluator is deterministic; on pi sessions without tests it is not. Should Engram only induce candidates from sessions whose success is attested by a deterministic signal (test run, exit code), and treat judge-only successes as a lower provenance trust?
