## Claim
Embedding similarity cannot tell a contradicted fact from a rephrased duplicate (AUROC 0.59), so RAG serves stale values structurally. A deterministic (subject, relation, object) supersession rule writing into a bi-temporal ledger, with no similarity threshold and no LLM call, matches RAG on static knowledge and takes stale-fact errors on evolving knowledge to about zero at RAG latency.

## Method
MemStrata stores facts as rows with `valid_from`, `valid_to` and `superseded_by`; active retrieval returns only rows whose interval is open (Sec. 4.1). On write, a clean triple is normalized on (subject, relation); if an active row with that key exists and the object differs, the old row's interval is closed and linked, and a new row opened; same object reinforces; no prior key stores (Sec. 4.2). Non-triple prose falls back to a similarity-plus-LLM "surprise gate" that drops only exact duplicates. The read path is cosine top-k over active rows, a staleness filter, then packing of original source sentences, with no LLM on the read path. Benchmarks: two static (domain, 50 project-fact items; locomo, 30 questions over 100 turns) and four evolving marker-free sets (code_mutation, config_migration, dependency_bump, api_evolution, 20 to 30 paired scenarios each) (Sec. 5). Answer model Qwen2.5-Coder-7B; judges Qwen2.5-Coder-3B; embedder nomic-embed-text. Eight conditions from no_memory through naive_rag, advanced_rag (LLM reranker), v6 variants, and temporal_v6 (full method).

## Key numbers
- Similarity calibration: 98 labeled pairs (32 duplicate, 22 merge, 22 contradict, 22 novel); AUROC 0.59; mean cosine 0.8119 for contradictions against 0.7998 for duplicates; best achievable precision 0.667 (Table 1, Sec. 5.1, App. A.3).
- Static accuracy: domain temporal_v6 0.82 against naive_rag 0.86; locomo 0.30 against 0.30 (Table 2, Sec. 5.2).
- Evolving accuracy, code / config / dependency / API: temporal_v6 1.00 / 1.00 / 1.00 / 0.95; naive_rag 0.43 / 0.25 / 0.20 / 0.40 (Table 2).
- Stale-fact error, abstention allowed / forced: naive_rag 0.10/0.40, 0.05/0.35, 0.05/0.15, 0.30/0.35; temporal_v6 0.03/0.03, 0/0, 0/0, 0/0 (Table 3, Sec. 5.3, App. A.2).
- Context compression on evolving sets about 47.5 to 50 percent, 0 percent on static (Sec. 5.4).
- Latency about 2.1 s for temporal_v6, naive_rag and v6_no_verify; about 16 to 18 s for LLM rerank or verify conditions, up to 24 s at p95 (Sec. 5.5, App. A.1, Tables 4 and 5).
- Extraction keys about 97 percent of supersessions on the templated benchmarks and about 44 percent on a messier natural-language set the author quarantined (Sec. 7).

## What Engram borrows
This is ADR 0005 with a measurement attached. The three ledger fields match `valid_from`, `valid_to` and `lineage`; the rule "an update with the same key and a different value closes the old interval and opens a new version" is the supersession behaviour ADR 0005 specifies, and this paper gives Engram its deterministic-tier expected-validity lint a target of zero stale exposure on templated updates (ADR 0008, L1). The marker-free evolving benchmarks (code mutation, config migration, dependency bump, API evolution) are exactly the coding-agent memory faults Engram will see in pi sessions and are candidates for `fixtures/faults/` in L2. The AUROC 0.59 result is the citation for ADR 0018's choice not to use embeddings for contradiction detection: near-duplicate by MinHash and contradiction by key match are different lints and must stay separate.

## What Engram does differently
MemStrata extracts the (subject, relation, object) key with a model at write time, and its own numbers show extraction drops to 44 percent on messy prose; Engram keeps the key optional on the item and treats the model-based contradiction lint (ADR 0008 tier 2) as the fallback, reported separately in H3. MemStrata uses ingestion order as time; Engram carries event time and ingestion time separately (Zep's model, ADR 0005) and supports `valid_at` reads. Engram also records who superseded what and under which policy as an event, which MemStrata does not need because it is single-principal.

## Risk to our claims
The 44 percent extraction rate on natural language (Sec. 7) means a deterministic supersession lint will miss more than half of real updates unless items are written with keys. H3 ("lints recover part of the loss") is then bounded by how many items Engram's write path can key deterministically. The plan should be to key items that come from tool results (file paths, package versions, config keys) where the subject and relation are structural, and to report keyed and unkeyed items separately.

## Open question
On static knowledge the ledger costs 4 points on the domain set (0.82 against 0.86, Table 2) for no benefit. Is that cost from the supersession rule firing on reinforcements, and would Engram see the same on LongMemEval's non-update categories?
