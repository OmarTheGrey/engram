## Claim
Skills built by analysing many trajectories in parallel and merging the lessons into one skill directory beat sequential skill editing and ReasoningBank-style retrieval memory, and transfer across model sizes.

## Method
A frozen agent runs on a task set and yields labelled success and failure trajectories. Success and error analyst sub-agents each propose patches to the skill. A merge step consolidates the patches, with programmatic conflict detection and format validation. It can deepen a human-written skill or start from a weak draft. Domains: office workflows, math reasoning, vision QA, WikiTableQuestions (abstract page; the body was not read).

## Key numbers
- Skills evolved by Qwen3.5-35B improve a Qwen3.5-122B agent by up to 57.65 absolute points on WikiTableQuestions (abstract).
- Other numbers: none stated in the sources read.

## What Engram borrows
Card D2 names Trace2Skill as the alternative to AWM. Its patch-then-merge shape suits Engram's versioning: each patch is a new item version in the lineage, a conflict is a lint, and the merged skill is the candidate that replay validation tests. Failure trajectories as input match ADR 0012's use of abandoned pi branches.

## What Engram does differently
The paper judges a skill by held-out task score and has no admission, retirement or provenance. Engram treats each merge as a candidate.

## Risk to our claims
ADR 0012 fixes AWM and the pre-registration forbids an induction method it does not name. Trace2Skill needs a pre-registration amendment before any H5 run, and a work-in-progress preprint is a weak anchor.

## Open question
Is a patch-and-merge generator better than AWM's single prompt on coding sessions, where there is no ground-truth label?
