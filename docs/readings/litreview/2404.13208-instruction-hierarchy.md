## Claim
Prompt injection and jailbreaks work because models treat text from every source as equally privileged. Training a model on an explicit hierarchy (system, user, model output, tool output) that tells it which conflicting instruction wins improves robustness substantially, including on unseen attacks, but the authors say the trained models are likely still vulnerable to strong adversaries.

## Method
The hierarchy orders sources by privilege: system message, user messages, the model's own outputs, then tool outputs such as search results (Sec. 2). Lower-privilege instructions are aligned if they fit the higher-level goal and should be followed, or misaligned if they oppose or are orthogonal to it and should be ignored, with refusal as fallback (Sec. 3). Training data is synthetic: context synthesis decomposes a compositional request across levels and trains the model to produce the full answer; context ignorance trains it to answer as if the lower-privilege instruction were absent (Sec. 3). Attack-specific sets cover open- and closed-domain prompt injection, indirect injection in browsing results from a red-teamer LLM, and system message extraction; jailbreaks get no training data. GPT-3.5 Turbo is tuned with SFT then RLHF on this plus capability data and compared with a baseline tuned without hierarchy data (Sec. 4). Evaluation covers TensorTrust, Gandalf, browsing and tool-use injections, jailbreakchat and over-refusal sets (App. B).

## Key numbers
- Robustness improved "by up to 63%" on in-distribution evaluations and system prompt extraction defence "improved by 63%" (Intro, Fig. 2).
- Generalisation to unseen attacks: jailbreak robustness "increases by over 30%" and "up to 34%" (Sec. 4, Fig. 3).
- Over-refusal: regressions on two tasks, System Message Probing Questions and Jailbreakchat with Allowed Prompts (Fig. 4).
- Prompting baseline (Table 3 prompt, Fig. 5): the trained model "far outperforms" prompting alone; adding the prompt to the trained model sometimes helps further.
- No per-bar values, dataset sizes or hyperparameters are stated in the sources read.

## What Engram borrows
The four-level ordering seeds the `provenance.kind` trust ordering in ADR 0004: user above model above tool, with document and compaction placed by policy. Aligned versus misaligned becomes the rule that a tool-sourced write may add content consistent with the scope's write policy but never change policy. The over-refusal regressions justify measuring U alongside A and F in every governance arm (ADR 0015). The authors' admission that trained models remain vulnerable is the one-line argument for H1: enforcement outside the model rather than instruction inside it.

## What Engram does differently
The instruction hierarchy is a training-time, in-model control over text the model has already seen. Engram enforces the hierarchy at the boundary, deciding which items the model sees and which writes land, with no learned component in the decision. The two are complementary: a hierarchy-trained model under an Engram plane is the expected deployment, and the plane's contribution is the gap between instruction-only and enforced conditions.

## Risk to our claims
If frontier models now internalise the hierarchy well enough that an instruction-only condition already yields near-zero leakage on GateMem, H1's enforcement gap shrinks to noise. The paper's own numbers (63 percent improvement, not elimination) argue against that, but the thesis must run the instruction condition on current models from three providers (ADR 0016) and report the gap as measured.

## Open question
Where do memory items sit in the hierarchy? They are model outputs at write time and tool-like context at read time. Step 0 should fix, in ADR 0004, whether a recalled item inherits its provenance kind's privilege or the privilege of the retrieval tool.
