## Claim
The damage from a wrong memory happens at the first decision point where the agent sees it: agents comply with conflicting memory 63 to 72 percent of the time regardless of model scale, success after compliance drops to a 17 to 31 percent floor, and recovery is rare. Because the floor is roughly constant, stronger agents lose more absolute performance per compliance, so memory consumption, not only retrieval quality, must be evaluated along the trajectory.

## Method
The Entry, Propagation, Recovery (E-P-R) framework asks where memory first changes an action, whether the change persists under early, persistent or late injection, and whether the agent returns to a correct path (Sec. 3.1, 3.2). Each (task, model) cell is paired with a no-memory trajectory on the same seed; the primary metric is success-rate difference. Recommendation Compliance Rate (RCR) is an LLM judge's call on whether step 1 executes the memory's first primitive; Damage Per Compliance (DPC) is the paired success loss on the compliant subset (Sec. 3.2). Testbeds: WebArena, 684 non-map tasks for a pre-check and a 77-task memory-sensitive subset with hand-authored DO/DON'T memories; MemTrapBench, 231 long-horizon browser tasks (median 15 steps) on a shared HTML/JS skeleton with four diagnostic families, Decoy (entry), Uptake (adoption), Grounding (a memory-referenced label absent from the AXTree) and Override (memory says ignore an explicit environment correction); memories drafted by Claude Opus 4.7 and hand-reviewed (Sec. 3.3, App. D). Models: Qwen3.5-9B, Qwen3.5-27B, Gemma-4-E4B-it, Gemma-4-26B-A4B-it, Gemini-3-Flash, greedy decoding via vLLM.

## Key numbers
- Full WebArena pre-check: Qwen3.5-9B minus 1.9pp (unconditional retrieval), minus 2.3 (relevance-gated); Qwen3.5-27B +1.7 and minus 1.7; memory does not reliably help (Table 1, Sec. 4.1).
- Persistent conflicting memory is the only schedule that hurts every model; peak drop minus 20.8pp on Qwen3.5-27B, minus 14.9 on Gemini-3-Flash; persistent vs early p=0.013 (Fig. 3, Sec. 4.2).
- WebArena 77, persistent conflicting: RCR 63 to 72 percent across models; post-compliance success 17 to 31 percent against no-memory 23 to 49 percent; DPC with CI excluding zero only for Qwen3.5-27B 25.5pp [11.8, 39.2] and Gemini-3-Flash 18.5pp [3.7, 33.3] (Table 2, Sec. 4.3).
- First-divergence probability reaches 0.86 to 0.94 for the Qwen3.5 models; after divergence, helpful-memory trajectories re-align by step 14 in 27 to 42 percent of cases, conflicting in 7 to 15 percent (Fig. 4).
- MemTrapBench persistent injection: helpful +25.5 to +30.7pp, conflicting minus 9.5 to minus 26.0pp, cross-task control within plus or minus 2.6pp; DPC 10.2 to 28.6pp with all four CIs excluding zero, p below .001 (Table 3, Sec. 4.4).
- Per-diagnostic conflicting damage: Decoy minus 24.2 to minus 43.5pp, the largest; Grounding helpful gains +57.9 to +73.7pp, the largest (Table 4).

## What Engram borrows
Two things for the evaluation protocol. First, RCR and DPC are the metrics that make the read explanation (ADR 0009) testable: if an admitting rule and provenance kind are shown to the model, does RCR on `model`-kind conflicting memories fall? That is a cheap H3 sub-experiment on MemTrapBench's Decoy family. Second, the paired no-memory trajectory on the same seed is exactly what ADR 0016 prescribes, and the finding that persistent injection is the harmful schedule says Engram's read filter should be evaluated under persistent injection, because pi's `context` hook injects on every turn. The Override family (memory tells the agent to ignore an environment correction) is a fixture for L2: a memory that contradicts a tool result should be flagged by the contradiction lint with the tool result as higher-trust provenance (ADR 0004).

## What Engram does differently
The paper varies what is injected and measures consumption; Engram controls what is injected and claims that provenance- and validity-filtered injection lowers the conflicting rate before consumption is reached. Engram does not try to change how the model consumes memory; it changes what reaches the model and records why, so the compliance trap is an argument for the plane, not against it.

## Risk to our claims
On the full WebArena set, memory of any kind was within plus or minus 2.3pp of no memory (Table 1). If the ungoverned condition does not help, a governed one that removes some harm will show a small absolute effect and H2's tax is measured against a baseline that is itself near zero. Engram should pick benchmarks where helpful memory has a measured positive control, as MemTrapBench's +25 to +31pp helpful arm does, and report DPC-style conditional losses rather than only mean accuracy.

## Open question
RCR is nearly constant across scale. Is compliance with injected memory an instruction-following property that a provenance tag in the prompt can lower, or do agents comply equally with a tagged low-trust memory? Fifty Decoy tasks with and without the tag would answer it.
