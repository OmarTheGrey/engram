## Claim
A 500-question benchmark over long timestamped chat histories shows commercial assistants and long-context models lose 30 to 60 percent of their accuracy when evidence is spread across sessions, and that indexing, retrieval and reading choices each move the result measurably.

## Method
Each instance is an ordered list of (timestamp, session) pairs followed by a question dated after the history (Sec. 3.1). Seven question types cover five abilities: information extraction, multi-session reasoning, knowledge updates, temporal reasoning, abstention (Sec. 3.2). Two scales: LongMemEval_S at about 115k tokens per question and LongMemEval_M at about 500 sessions and 1.5M tokens (Sec. 3.2). A gpt-4o-2024-08-06 judge scores answers, with agreement above 97 percent with human experts (Sec. 3.3, Table 6). Section 4 frames memory as indexing, retrieval and reading with four control points (value, key, query, reading strategy), tested with Stella V5 1.5B as retriever and GPT-4o, Llama 3.1 70B and 8B as readers (Sec. 5.1).

## Key numbers
- 500 questions, 50k sessions, 30 abstention questions built as false-premise variants (Sec. 3.2, Table 1).
- ChatGPT (GPT-4o) 0.5773 vs 0.9184 offline reading, a 37 percent drop; Coze 0.3299, 64 percent; 97 sampled questions (Sec. 3.4, Figure 3a).
- Oracle to S drop: GPT-4o 30.3 percent, Llama 3.1 70B 55.1, Phi-3 14B 45.9 (Sec. 3.4, Figure 3b).
- Fact-augmented keys: round-level Recall@5 0.582 to 0.644, QA 0.615 to 0.638; average gains 9.4 percent recall, 5.4 percent accuracy (Sec. 5.3, Table 3).
- Time-aware query expansion, temporal subset: Recall@5 0.489 to 0.526 with GPT-4o, 0.481 with Llama 3.1 8B (Sec. 5.4, Table 4).
- Judge agreement 0.98 on GPT-4o answers, 0.97 on Llama answers; lowest category single-session-preference 0.90 (Table 6).

## What Engram borrows
Knowledge-update and temporal types are the direct test of ADR 0005: a governed read must return the latest valid version and the explanation must show the validity window applied. Abstention questions become a lint fixture: answering a false premise means an unsupported item was admitted (ADR 0008, L1). The input format and the `question_id` plus `hypothesis` JSONL output are the contract the vendored judge consumes (ADR 0015). Recall@k against labelled evidence sessions gives a judge-free retrieval metric that H2 uses to separate retrieval loss from reading loss.

## What Engram does differently
LongMemEval scores a memory system's answers and does not ask who wrote the memory or under what rule. Engram holds the store fixed and varies only governance, so condition differences are attributable to policy, not indexing design. The paper's optimizations are store features Engram leaves to the adapter.

## Risk to our claims
The judge is part of the benchmark. If judge disagreement concentrates in update and preference questions (the 0.90 category), the H1 effect on exactly the questions governance targets is the noisiest. Mitigation: the 50-item label audit in ADR 0015, stratified to over-sample those types, and H1 reported with and without them.

## Open question
The repository says sessions were cleaned in September 2025 and a V2 for agentic contexts exists. Which revision do we pin, and do we run both histories on one condition to measure how much cleaning moves the score?

## Notes
Dataset: 500 questions, seven types, two history scales plus an oracle file. Task type: QA over chat history. Judge: model-based (GPT-4o) with a human meta-evaluation. Plug-in: feed the history to any system, emit JSONL, run `src/evaluation/evaluate_qa.py` then `print_qa_metrics.py`; no benchmark code changes. Licence: MIT (README). Data on Hugging Face. Version read: v2, March 2025. Per-type counts appear only as unlabelled percentages in Figure 9. The abstract says a 30 percent drop while the intro says about 60 percent for LongMemEval_S. No limitations section was found; the commercial pilot used 97 questions with histories about ten times shorter than S (Sec. 3.4).
