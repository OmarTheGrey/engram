## Claim
Procedural memory for deployed agents should be compiled only from verified task attempts, versioned, gated before activation and ranked by verified use, and doing so lifts weaker executor models without training.

## Method
Zep Agent Skills records each attempt as a Trace (ordered events, an outcome, a verification strength). A compiler with Reflector and Curator roles turns Traces into versioned Skills that cite their evidence. Admission gates decide which Skills become active; verified use outcomes feed search rank. Agents fetch Skills through lexical search over an API or MCP. Self-reported checks are not enough for admission, and conflicting verification records on a Trace block automatic admission. Evaluated on tau3-bench banking, AppWorld and EnterpriseOps-Gym with teacher-compiled skills and three weaker executors, and on ALFWorld with skills compiled from a small model's runs.

## Key numbers
- Pass-rate gains of 4.5 to 18.8 points for three weaker executors at every reasoning effort (abstract).
- ALFWorld gains comparable to or larger than reported for continuous fine-tuning, without training (abstract).

## What Engram borrows
The vocabulary of verification strength on a trace and "conflicting verification blocks admission" fit ADR 0011 admission rules for Distill. Search rank driven by verified use outcomes is the outcome signal Library Drift (2605.19576) says retirement needs. Skills delivered over MCP match our own surface.

## What Engram does differently
Zep admits through its own gates inside its service; Engram admits after replay validation and logs the decision as an event with a reason, and can retire on drift. Zep's compilation uses a teacher model's traces; H5 uses Agent Workflow Memory in both arms.

## Risk to our claims
This is a commercial system reporting gains from ungoverned-plus-verified skills. For H5 it raises the bar: a "C2 without governance" arm that already requires verified traces may show less of a governance gap than a naive induction arm. Action: state in the H5 write-up what verification the C2 arm gets.

## Open question
Is verification strength (self-reported, tool-checked, user-confirmed) a field Distill should store on each trace, and does it map to provenance kind?
