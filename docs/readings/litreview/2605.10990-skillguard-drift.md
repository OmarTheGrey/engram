## Claim
A skill goes stale when an environment assumption it depends on (a pinned version, an endpoint, a schema field, an auth mechanism) stops holding, and the right unit of monitoring is the assumption's role, not its raw value. Extracting executable environment contracts from skill documents and checking only role-bearing ones gives zero false alarms on 599 negatives, 100 percent precision on known drift, and localised repair that succeeds 78 percent of the time against 10 percent without localisation.

## Method
SkillGuard extracts contracts in two passes: 15 regex families for URLs, version constraints, imports, API paths, auth patterns, Docker images, GitHub Actions, env vars, cloud regions, CLI flags and config filenames, then a semantic LLM pass that records type, role, value and evidence span for implicit assumptions; skills yield 15 to 40 records each, median 22 (Sec. 4.1). Incidental mentions (comments, badges, examples) are suppressed; only operational contracts can trigger a violation (Sec. 4.1, App. B). Known-drift checking matches contracts to drift events with exact, substring, two-token and one-token type-compatible backoffs; live checking tests operational contracts against package registries, URL responses and ecosystem conventions (Sec. 4.2). Repair generates two candidates per violation and keeps the first that passes a strict literal verifier (Sec. 4.3). DriftBench has 880 pairs: a controlled split of 174 drift pairs, 49 identity pairs, 300 formatting hard negatives and 250 semantic hard negatives over 8 drift types from 49 SWE-Skills-Bench skills, plus 107 real drifts from PyPI, npm, GitHub Actions and Docker Hub over 22 skills (Table 1). Backbones: Qwen3.6-Plus, Qwen3-235B-A22B, DeepSeek-V3.2, DeepSeek-R1, GLM-5.1. A pre-registered open-world study froze drift labels on 49 real skills (22 drifted, 27 fresh) before running the monitor (Sec. 5.2).

## Key numbers
- Contract-free CI probes: 40 percent false positive rate; SkillGuard: 0 false positives on 599 negatives, Wilson 95 percent CI [0, 0.6] percent (Sec. 5.1, Fig. 3).
- Baselines: grep/diff recall 30 percent; Dependabot-style recall 11 percent at 10 percent FPR; NL2Contract-style recall 45 percent at 0 percent FPR (Sec. 5.1, Fig. 3).
- Known-drift precision 100 percent on all five backbones; recall Qwen3.6-Plus 76 percent [62, 88], DeepSeek-R1 62, DeepSeek-V3.2 57, GLM-5.1 54, Qwen3-235B-A22B 24 (Table 2).
- Live study on 49 skills: 14 flagged, TP 12, FP 2, FN 10, TN 25; precision 86, recall 55, FPR 7 percent; the two FPs were later adjudicated as genuine drift (Sec. 5.2, Fig. 4A).
- Repair success: no localisation 10 percent; plain drift text 60; failed-contract localisation 78 (p below 1e-5 against no localisation); Self-refine three rounds 80; full drift-spec rewrite 78; tokens per skill about 10K contract-guided against about 18K Self-refine (Sec. 5.3, Fig. 4B).
- Role audit on 200 mentions: precision 89.5, recall 83.4, F1 86.3 percent; role recall on semantic hard negatives 72.7 percent (Sec. 6.1).
- Per-type detection on Qwen3.6-Plus: URL and version 100 percent; config, deprecation, schema 60 to 67 percent; auth drift detected 67 percent and repaired 0 percent on 3 examples (Sec. 6.3).

## What Engram borrows
ADR 0011 says a procedure is retired when its "environment hash" changes; this paper says what to hash. A procedural item should carry a `contracts` list of (type, role, value, evidence span) extracted at induction time (ADR 0012, D2), and the drift signal is a contract check, not only a smoothed success rate. The deterministic tier of that check (the 15 regex families, checked against lockfiles, registries and the repository) is a lint in ADR 0008's first tier and can run without a model; the semantic pass is tier two. The operational-versus-incidental distinction is a lint rule: a version string in an example block is not a contract. DriftBench's 880 pairs are the fixture set for D3 (retirement on drift) and the 40 percent FPR of naive probes is the number Engram's retirement rule must beat so that H5 is not killed by alert fatigue. Localised repair specs are the model for how a retired procedure re-enters as a candidate (ADR 0011) with its violated contract attached.

## What Engram does differently
SkillGuard monitors a static library of human- or LLM-authored skill documents; Engram's procedures are mined from pi sessions (ADR 0012) and admitted by replay (ADR 0011), so the contract check sits beside replay validation rather than replacing it, and a contract violation is an event with lineage rather than an alert. Engram does not attempt automatic repair in v1; a violated contract retires the item and a human or a later session re-induces it.

## Risk to our claims
Recall on known drift ranges from 24 to 76 percent by backbone (Table 2), and live recall is 55 percent. If Engram's retirement rule depends on a model-extracted contract set, roughly half of real drift goes undetected and H5's "retired on drift" clause is weaker than stated. Engram should report the deterministic-tier recall separately (what the regex families and replay catch without a model) and state the model-based tier's recall as a measured, backbone-dependent number.

## Open question
Replay validation (ADR 0011) catches drift only when the held-out task exercises the drifted contract. What fraction of DriftBench's 107 real drifts would a k-of-n replay on the skill's own examples catch, and is contract checking then mostly a cheaper early warning or a genuinely different detector?
