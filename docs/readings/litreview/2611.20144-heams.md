## Claim
A memory system is the custodian of a user's persistent information, so it should be judged on performance, efficiency, privacy, user sovereignty and security together, and a governance layer that wraps any memory system changes those scores strongly.

## Method
The authors define behavioural desiderata (Table 1) and assemble a benchmark suite (Table 2) from published sets (LoCoMo, LongMemEval, Evo-Memory, BEAM, STALE, MPBench) and four new ones (Contextual Integrity for privacy; Transparency, Editability and Erasability, and Retention Policy for user sovereignty). They build MilaMem, a prototype with independently configurable operations, and a governance layer (Sec. 4.2) that wraps any memory system with retention policies (screen before storage) and recall policies (screen retrieved candidates before disclosure; items stay stored). Policies are binary keep or drop and can be deterministic, free-text read by an LLM, or hybrid; every experiment uses free-text policies. Systems compared: no memory, in-context, Mem0, Letta, HippoRAG 2, MilaMem; the governance layer is evaluated only with MilaMem (Table 3, caption).

## Key numbers
- Every memory system beats no memory by at least 14 points on LoCoMo, LongMemEval, BEAM and STALE; no system wins all (Table 4).
- HippoRAG 2 is helpful on 94.79 percent of privacy tasks but leaks on 71.74 percent (Table 5).
- Recall governance on MilaMem cuts scenario leakage from 57.61 to 31.82 percent, costs 4.80 points of helpfulness, and gives the highest helpful and leak-free share, 45.95 percent (Table 5).
- Erase success is 0.00 percent for in-context and Mem0; edit success 0.61 and 2.44 percent (Table 6).
- Retention governance lowers MilaMem's prohibited-recall upper bound from 100.00 to 15.63 percent while permitted recall falls from 100.00 to 84.47 percent (Table 7). On MPBench, resistance is 40.00 percent without governance, 85.00 with retention only, 82.22 with recall only and 88.61 with both, over 360 attacks (Table 8).

## What Engram borrows
Its desiderata table is a ready checklist for the related-work comparison and for the E8 inspector. The Contextual Integrity and Transparency/Editability/Erasability suites are candidate secondary benchmarks for the Twin pillar (consent, offboarding, correction). The paired "helpful and leak-free" share is a better headline than leakage alone for H2.

## What Engram does differently
HEAMS' governance layer supports deterministic substring and metadata rules, free text read by an LLM, or hybrid; every reported experiment uses free text read by gpt-4o-mini. Its wrapper logs recall decisions and retention drops with an action, reason, policy id and decision source, as run records; no code rebuilds state or re-decides from them. Engram's gate is deterministic only, its log is the source of truth that replays state, and it supports grants and an explain path. HEAMS covers one user's memory, has no scope or grant model across principals, and does not govern delete or consolidate.

## Risk to our claims
This is the nearest published neighbour to "a governance layer that wraps any memory system", built so that one policy can be compared across systems (Sec. 4.2) but evaluated only with MilaMem (Table 3, caption). The claim now reads "the first deterministic, event-logged, replayable control plane across memory stores, with a pre-registered measurement of its governance tax" (`docs/research/positioning.md`). Action: cite as a threat in related work, state the difference, and consider running HEAMS' privacy and sovereignty suites as a side result if licence and pin allow.

## Open question
