## Claim
A protective layer around the model, not a better model, can make an agent secure against prompt injection: untrusted data never reaches the control flow, and capabilities on values decide which tool calls may use them.

## Method
CaMeL extracts the control and data flow from the trusted user query, so data the model retrieves cannot change the program flow. Capabilities attached to values block exfiltration over unauthorised flows, enforced when a tool is called. Evaluated on AgentDojo. Only the abstract page was read; the interpreter design and the privileged and quarantined model split are from memory of the paper and not verified here.

## Key numbers
- Solves 77 percent of AgentDojo tasks with provable security, against 84 percent for an undefended system (abstract).

## What Engram borrows
The idea that a value carries capabilities that a deterministic check reads at the point of use. Engram's analogue is the provenance kind plus the grant: `model` and `compaction` content carries a label the write gate and read filter check (ADR 0004, 0007). A concrete borrow is a per-item taint derived from provenance and lineage, checked by the gate, never claimed by the model.

## What Engram does differently
CaMeL secures an agent's tool calls by interpreting a plan; Engram secures what is stored and returned, and does not control the agent's plan. The two compose: CaMeL for the session, Engram for what outlives it.

## Risk to our claims
The utility cost (77 against 84) is the price of provable security. A reviewer will ask the same of Engram's governance tax; H1 already measures it.

## Open question
Can the pi extension carry a taint label on tool results into the write call, so a write whose content derives from a web tool result is denied without a model judging it?
