## Claim
A model can write Cedar policies reliably if the requirement is first decomposed into reviewed "intent atoms" and a solver-based verifier checks each candidate against them, feeding failures back as repair signals.

## Method
Natural-language requirements become small intent atoms that are validated mechanically and reviewed by humans. A model proposes a policy; a verifier checks it against the approved target (a search summary says cedar symcc with cvc5); each failure says broaden, narrow or restructure. Evaluated on CedarBench. Only the abstract was read.

## Key numbers
- 221 tasks in CedarBench, all converged (abstract).
- Three case studies: healthcare, education, conference management (abstract).

## What Engram borrows
The floor and ceiling pattern: an Engram policy change is accepted only if it implies the floor (what must stay readable) and is implied by the ceiling (what must never become readable). Lands in AB-POL-2's acceptance and the policy-diff gate in AB-POL-5. A model-drafted policy proposal would enter through an injected ModelCall (rule 4), never inside core.

## What Engram does differently
Engram's policy is a typed object, not free Cedar, so the generation target is a schema-constrained edit rather than program synthesis.

## Risk to our claims
None to the thesis claims. It shows verifier-guided repair is a published pattern, so novelty must rest on the memory-specific invariants, not on the loop.

## Open question
