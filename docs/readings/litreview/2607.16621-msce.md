## Claim
Memory and skills should co-evolve under governance: step traces are valued, well-supported procedural policies with positive estimated gain become callable skills that keep links to their evidence, and skills carry a reliability score, an applicability boundary, and a probationary, active, archived lifecycle.

## Method
Three memory levels (Sec. 3): L1 trace memory stores (state, action, observation, self-reflection, value) per step; L2 policy memory holds reusable procedures with trigger, procedure, verification, applicability boundary, and supporting L1 evidence; L3 environmental cognition holds declarative facts about the environment, each linked to supporting L2 policies. A skill library holds callable skills derived from eligible L2 policies, with evidence anchors, decision guidance and a reliability estimate. Promotion: L1 to L2 needs trace value at or above v_min and a signature seen in at least n_min distinct episodes; L2 to L3 needs a cohort of at least m policies above similarity theta_sim; L2 to skill needs supporting traces, gain G above theta_G, recent evidence fitting the current trigger and boundary, and a deterministic verifier checking schema, evidence grounding, tool whitelist and coverage. Gain is the mean value with the policy minus a shrunk mean without it, called a heuristic, not a causal estimate (Sec. 3, Table 6). Reflection-weighted value backfilling spreads sparse end-of-task feedback over dense local reflections. Backbone GPT-5.2, auxiliary operators GPT-4o, simulated mentor Opus 4.7 Max, runtime OpenClaw v2026.5.7 (Sec. 4, App. D.2). Benchmarks EvoAgentBench (IR, Math, SE, Code, KW) and LoCoMo; baselines Vanilla, EverOS, Memento, MemSkill, EvoSkill, OpenSpace, SkillFlow-Evolve.

## Key numbers
- Lifecycle: a new skill is probationary; it becomes active when reliability exceeds theta_active = 0.6 after at least n_prob = 1 probationary invocation; archived on repeated failure, explicit rejection, or source policy with negative gain, theta_archive = 0.2 (Sec. 3, Table 6).
- Reliability eta = (n_pass + 1) / (n_trial + 2); explicit user feedback moves it by delta = 0.1 (Sec. 3, Table 6).
- Other thresholds (Table 6): v_min 0.1, n_min 2, m 2, theta_sim 0.62, theta_G 0, shrinkage prior b 0.5 with pseudo-count N_0 5, tau_V 0.5.
- Boundary narrowing: user rejection or a boundary violation shrinks the applicability boundary; no formal algorithm given (Table 4, App. B.8).
- EvoAgentBench Pass@1: MSCE 26.15 IR, 47.00 Math, 53.85 SE, 61.54 Code, 53.45 KW; strongest baseline 21.54, 43.00, 38.46, 61.54 (tie), 48.28 (Table 1).
- LoCoMo: MSCE 61.23 judge score, 49.89 F1; SkillFlow-Evolve 59.22, 48.71 (Table 2).
- Ablation Pass@1 on IR / Math / SE / Code / KW: full 26.15 / 47.00 / 53.85 / 61.54 / 53.45; without skill crystallization 20.00 / 39.00 / 42.31 / 53.85 / 44.83; flat memory 10.77 / 31.00 / 34.62 / 56.41 / 37.93 (Table 3).
- Lifelong gains p0 to p100: +17.00 Math, +15.39 SE, +13.84 IR (Figure 3).

## What Engram borrows
The reliability formula is the smoothed success rate ADR 0011 names; it lands on the procedure item as a field and in D4 with theta_active and theta_archive as pre-registered defaults to argue over (S0.12). Boundary narrowing on rejection is the rule that a human reject narrows the trigger instead of deleting the item. Evidence anchors become provenance links from a procedure to the pi session entries it was induced from (ADR 0004). The deterministic verifier (schema, grounding, tool whitelist) becomes a candidate lint tier (ADR 0008).

## What Engram does differently
MSCE has three levels inside one memory system; Engram has one procedural class beside episodic sessions, no L3, and one lifecycle for every class. MSCE activates on estimated gain from observed episodes; Engram activates on replay against held-out tasks. Every Engram transition is a logged event with a reason; MSCE's operations (Table 4) are internal.

## Risk to our claims
With n_prob = 1 and theta_active = 0.6, eta after one pass is (1 + 1) / (1 + 2), about 0.67, so a skill activates after a single success. If the field converges on one-success activation and still reports the Table 3 gains, Engram's k of n gate looks over-conservative and could starve the active set, hurting H5 on the utility side. Mitigation: pre-register k and n, and report candidate starvation (candidates never reaching n replays) as a D4 number.

## Open question
What k and n give the same false-activation rate as eta above 0.6 after one trial, under the Wilson bound SKILL.nb uses? This is a step-0 calculation, not an experiment.
