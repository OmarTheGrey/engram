## Claim
When a user asks an agent to forget a specific piece of personal information, no current memory system does it: across six mainstream systems and three backbones, no system passes more than 1.5 percent of forget requests end to end, and most pass none, either leaving the information extractable under simple attacks or deleting far more than was asked.

## Method
Bemula is 50 multi-session dialogue instances carrying 135 forget requests of six types and 1,742 test questions (abstract). Each dialogue has a paired control version without the forget requests, so a system earns credit for forgetting only if it demonstrably stored the target in the control run; this blocks the trivial win of never storing anything. Five test suites measure storage (was it remembered), removal (is the requested item gone), preservation (are unrelated memories intact), relearning (does a similar later fact re-establish it) and extraction resistance (can simple attacks pull it back). Six memory systems and three backbone LLMs are evaluated, plus a full-context LLM baseline on two backbones (abstract). The names of the six systems, three backbones and six request types are in the body, which could not be fetched (see Notes).

## Key numbers
- 50 dialogue instances, 135 forget requests, 6 request types, 1,742 test questions, 5 test suites (abstract).
- End-to-end pass rate: no system above 1.5 percent of forget requests; most systems at 0 percent (abstract).
- Six memory systems, three backbones, full-context baseline on two of the three (abstract).
- No per-system or per-suite figures are stated in the sources read.

## What Engram borrows
The paired-control design is the right protocol for Engram's erasure test (ADR 0010, Twin erasure in ADR 0021): a retire or delete event only counts if the same item is shown recalled in the matched ungoverned run. The five suites map onto events the plane already emits: storage is the write event, removal is the retire event plus a read that returns nothing, preservation is the orphan and duplicate lints not firing on neighbours, relearning is a write-gate rule that a retired item's content hash or near-duplicate (ADR 0018) cannot be re-admitted without a new user event, and extraction resistance is invariant 1 tested with GateMem-style leak targets (ADR 0006, S0.9). Bemula is a candidate addition to the six benchmarks in ADR 0015 for the forgetting axis, which GateMem covers only with 763 checkpoints inside a broader score.

## What Engram does differently
Bemula measures whether the memory system, including its model-driven extraction and update, honours a natural-language forget request. Engram does not ask the model to interpret the request: a forget is a typed event addressed to an item id or a scope-plus-query, applied by the plane, and the over-deletion failure they report becomes a lineage question (which versions did the retire event touch, each with a reason). The relearning suite is where Engram differs most: ADR 0010 retires rather than deletes, so a retired item stays as evidence that its content must not be re-admitted, which is the opposite of the systems Bemula tests, where deletion erases the record of the request.

## Risk to our claims
Their extraction-attack suite will test Engram's retire-not-delete stance directly. A retired item that stays in the store as a projection (ADR 0003) and is only filtered at read is extractable by any path that bypasses the read filter, including a store's native search or a compaction summary written before the retire. If Engram scores like the six systems here, H1 is unsupported on the forgetting axis. The mitigation is ADR 0014's no-bypass rule plus a lint that scans `compaction` items for content of retired items (an extension of the source-changed lint).

## Open question
Which of the six request types do the systems fail on, and is any of them a type Engram cannot express as a typed event (for example "forget everything about my health" versus "forget that I said X")? That decides whether the twin's erasure report needs a model-based resolver at all.
