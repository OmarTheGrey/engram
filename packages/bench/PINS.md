## Notes per pin

- **GateMem.** Open-label: `query_type`, `expected_action`, `judge_spec` and `leak_targets` sit in the files the agent reads, so the bench adapter strips them before anything reaches the plane. The literature-review note (`docs/readings/litreview/2606.18829-gatemem.md`) says no code was found; the repository above supersedes it.
- **MEM-INV-Bench.** Checked on 2026-10-29 the way S0.6 checked the others (`gh api repos/yedidel/mem-inv-bench`, its tree and `README.md`, `REPRODUCE.md`, `release.json`, `CITATION.cff`, `THIRD_PARTY_NOTICES.md` at `cf3c9a4`; the Hugging Face API for the dataset; the paper, arXiv 2606.24322, HTTP 200). Code and data are released, which the literature-review note had not checked. It is not MPBench's design: it measures whether poisoned memory drives a consequential action (pay, wire, purchase, setting change, data send) past an authorization monitor, across laundering channels, not whether a poisoned write is stored and later retrieved, so H1's metric on this arm is that (`docs/research/preregistration.md`). The released records are recorded evidence of the authors' runs (4,384 records, five plans) and replay offline; scoring a new condition means running the cases live, which the runner does through card B4's port rather than upstream's runners in `code/`. The one open item at the check is pull request #1, adding an optional contextual and temporal authority extension benchmark. Card B4 (2026-10-29) read the code at the commit: the laundering-channel cases are not in the Parquet tables (those hold the five extension plans) but authored in `code/scenarios.py` (8 attack scenarios times 4 channels, direct, summarize, tool_echo and corroborate, plus 6 legitimate actions) with memory built by `code/exp1_propensity.py`; outcomes are scored by the rule bucketer `review.bucket_of` with the recorded readings of `adjudication.py` first (`score.verdict_of`); the monitor `code/tma.py` gates the action, not the memory write. The 24-case subset, its selection rule and its sources are in `fixtures/bench/mem-inv-bench/README.md`; PR 3 of the plan vendored all 38 cases into `fixtures/bench/mem-inv-bench/full/` under the same manifest, and `engram doctor` checks every vendored file against the pinned commit.
- **LongMemEval.** Results on the cleaned files are not comparable with the original 2024 files.
- **MERIT.** Single-group and unreviewed; its `HYPOTHESES.md` refers to a `prereg-v1` tag that does not exist.
- **tau2-bench.** Pinned to the `v1.0.1` release rather than the moving head (`96a3ef9`, 2026-10-15): the repository is now tau3-bench and its numbers are not comparable with the 2025 paper. It does not test memory; it is the tool-use harness a memory layer is inserted into.
